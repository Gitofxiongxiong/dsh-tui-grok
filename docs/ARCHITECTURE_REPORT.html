分析时间：2026-08-25 · 方法：3 个并行子 agent 源码深潜（DSH 外置 TS 插件套件 / Rust host 层 / Grok UI 层）+ 主 agent 综合 · 纯只读分析，未修改任何代码、协议或 vendor 内容

1. 项目概览

一句话定位：dsh-pager-grok（仓库名 dsh-tui-grok）是 DeepSeek Harness 的原生终端 UI 实验项目：保持 Grok Build TUI 的前端样式、布局、交互状态机、快捷键、鼠标行为、滚动/选择、主题、动效和终端生命周期，把它适配到 DeepSeek Harness。它不是"重新实现一个类似的 pager"，而是优先复刻 Grok Build 的完整 UI 组件交互和视觉效果。

项目从 dsh-pager 拆出并接入 Grok Build UI，是独立仓库；DeepSeek Harness 原仓库只作为外部 backend/profile 宿主。本仓库包含：Rust TUI（9 个 crate + 2 个 Grok vendor crate）、DSH-neutral adapter、协议/transport、以及 4 个外置 TypeScript 插件包。

三个不可改变的决策（设计契约）

决策含义
Grok 前端是视觉和交互真源组件树、布局算法、主题 token、focus/Esc ladder、滚动/选择/鼠标状态机优先从 Grok 复制或结构性移植
DSH 是数据和副作用真源session、事件顺序、连接、队列、交互请求、generation、RPC receipt 只能来自 DeepSeek Harness
适配层是唯一接缝view 不调用 RPC，runtime 不把 Grok 类型带进 host；差异集中在 DTO、projection、Intent/Effect adapter

来源：docs/GROK_BUILD_TUI_DEEPSEEK_ADAPTATION_PLAN.md（§0.3）、docs/ARCHITECTURE.md、AGENTS.md。

4. 核心数据流

RPC notifications
       │
       ▼
SessionState / ControlPlaneStore
       │  snapshot + commands
       ▼
GrokHostAdapter ──────► Grok views/widgets ──────► terminal
       ▲                         │
       └────── UiEffect ◄────────┘
  • 唯一允许跨层的方向是 runtime → adapter → Grok view；Grok view 不反向调用 RPC（未来可把同一 host adapter 接到 Codex CLI 等兼容 harness）
  • UI 的每个用户意图都经过 UiIntent → UiEffect → receipt/notification 边界；最终状态以 Harness 的 authoritative snapshot 为准
  • session、request、generation、sequence、render entry、queue item、interaction 均有稳定 identity；replay/live、attach/detach、reconnect、partial replacement、queue revision 由 host authoritative state 收敛
  • 任何 effect 经 Intent→Effect→receipt 发送，不能因重绘重复发 RPC；stale/gone/duplicate/unsupported/error 显式进入诊断或 Grok status/modal

来源：docs/ARCHITECTURE.md（数据流）、AGENTS.md（异步、身份和效果）。各层实现细节见第 5–7 章。

5. DSH 外置 TypeScript 插件套件专题

四包三层架构：tui-protocol（纯协议/codec 库）→ tui-server（Cordis stdio gateway + 有界 control-plane 缓存）→ tui-embedded（纯 bundle patch）+ tui-session-projection-recovery（装饰 session.list 的冷行恢复插件）。依赖方向单一向下，全部只依赖 DSH 官方 0.1.0-rc.8 发布包，不 fork、不改 Harness 源码。

tui-protocol（纯库，无 workspace 依赖）

tui-server ──workspace:*──► tui-protocol
   ▲ deps: workspace:*

  • 协议双端同构：TS tui-protocol 是服务端参考定义（协议"原点"：含 codec、control-plane 基线、错误码、方法表），Rust dsh-pager-protocol 是客户端镜像（+自持业务 DTO）。共享同一 wire 常量（TUI_PROTOCOL_VERSION=1）、camelCase/kebab-case wire 名，以及字节级相同的 hello fixtures（两侧 diff 验证 identical）；Rust 客户端以 embedded_hello_params 走 tui.hello 握手并校验版本/服务名
  • 不对称处：TS 额外拥有 control-plane 基线类型与 TUI_UNARY_METHOD_SET 方法表；Rust 额外拥有转发业务方法的客户端 DTO（SessionPromptParams、QueueAction、Subagent* 等），TS server 对这些 params 保持 unknown 不透明（gateway 校验）；Rust 订阅 receipt 全字段 default 兼容旧网关 {}
  • 文档小瑕疵（未确认）：crates/dsh-pager-protocol/src/lib.rs:1 文档写 "shared with @deepseek-ai/dsh-tui-protocol"，疑似外置化前的旧官方名残留（实际包名 @dsh-pager-grok/tui-protocol）

  • 开发期：scripts/setup-dev-profile.sh + dsh-tui-common.sh——解析 DSH_HARNESS_ROOT/DSH_HOME/DSH_TUI_PROFILE → 缺依赖时 pnpm install --frozen-lockfile → pnpm run build:ts → 一次 dsh plugin add 源码 link 四个本地包目录进 $DSH_HOME/profiles/<name>；profile 三查（is_managed/is_ready/links_current_repo），不写入 Harness checkout

5.4 TS 侧与 Rust 侧职责边界

侧拥有不拥有
Rust crates（dsh-pager / dsh-pager-protocol / dsh-pager-grok-ui）transport（stdio 子进程 RPC）、SessionState/loader、control-plane 真源、Grok 派生 UI/交互/布局、转发业务方法的客户端 DTO不 import Grok view/ratatui Frame 进 session；view 不得直持 RpcTransport

6. Rust host 层

总览：host 层是「系统真源」，UI 是「可替换消费者」——crates/dsh-pager/src/lib.rs 声明 "runtime facade only"，只持有协议/传输/会话/control plane/presentation 数据模型，公开 API 以 DTO（DshPresentationModel、DshRenderEntry、DshQueueItem）暴露；不 import Grok view、不持有 ratatui Frame（仅用 ratatui::text::Line 等中性类型）。

7.2 Intent → Effect → Receipt 链路

  • 定义层（src/effects.rs）：UiIntent（17 种语义意图：SubmitPrompt/AttachSession/QueueMutation/RespondInteraction/SetSessionMode…）→ compile_intent（纯函数，含 per-intent dedupe_key）→ UiEffect；UiContext{session_id,generation,request_id} 防止 view 拿到 SessionState；OperationKey 幂等/诊断身份；UiEffectStatus 九态（Accepted/Queued/Pending/Rejected/Stale/Conflict/Unsupported/Failed/Timeout）；EffectLedger（分配 ui-N request id、去重、上限 1024）
  • 双执行路径：同步 DshEffectSink::dispatch_effect（prepare → ledger 去重 → 调 dsh_pager::* RPC → classify_effect_error → receipt）；异步 AsyncEffectExecutor（encode_async_request → transport.begin_call_value → Pending receipt → poll_call_value → UiEffectCompletion）

  • view 层零 transport：全仓 grep 确认 RpcTransport 只出现在 effects.rs 与 runtime.rs，views/ 与 vendor/ 零命中 —— 符合 AGENTS.md 硬约束
