# 修复本地测试门禁

> 记录时间：2026-08-29 20:11:59 +0800
> 操作者/agent：Codex
> 状态：partial

## 目标与背景

`dsh-tui-grok` 在 Rust 1.98.0、Node 24.19.0 的本地门禁中暴露四项可重复问题：

1. `/login` 功能提交遗漏了 `src/slash.rs` 的 source manifest vendored hash 同步；
2. Node 24 对 pipe 执行单次 128 KiB `writeSync` 时可返回 `EAGAIN`，使 stderr drain contract 测试在进入 Rust transport 断言前就失败；
3. Rust 1.98 clippy 要求 `io::ErrorKind::Other` 构造使用 `io::Error::other`；
4. PTY smoke 在同一次 `os.write` 中发送 `/login\r`，没有等待 slash suggestion 稳定就提交，造成时序失败。真实 PTY 中 `/login` 可正常渲染，拆分输入并等待稳定帧后 smoke 可通过。

目标是修复测试本身的跨版本/backpressure/稳定帧契约，同步 source manifest，不改变 `dsh-tui-grok` 产品行为或 Grok-derived UI 实现。

## 设计契约和复用依据

- 对应长期计划章节：2.5 依赖和源码契约、2.8 变更前记录、M0.2/M0.4 来源与基线、M9.7 backend stderr/子进程生命周期、M10 PTY 门禁。
- Grok source path、commit、SOURCE_REV：本批不修改 Grok-derived source；对照 checkout 已回到 mirror commit `19d42e35c07a9c9244f03f6df0c4c353f970d4f9`（SOURCE_REV `7d67deacbeb1c1093fdb4f9bcbfab2630e18a6aa`）。
- 复用等级：D（stderr/mock/PTY 测试基础设施不复用 Grok runtime）；manifest 仅同步已审计的 B/A1 `src/slash.rs` 当前 hash。
- Node stderr producer 使用 stream backpressure/drain，保持 128 KiB flood 规模和尾部 marker；Rust transport 仍必须排空 pipe 才能通过。
- PTY 在输入 `/login` 文本后等待 exact suggestion 稳定，再单独发 Enter；不放宽弹窗文案、密钥遮罩、泄漏检查或 terminal restore 断言。

## 风险、回滚和依赖

- 风险：PTY 稳定等待若只匹配 prompt 文本，可能没有证明 suggestion 已渲染；因此必须同时匹配 `/login` 行和其描述。
- 风险：异步 stderr 写入必须在建立 stdin readline 之前等待 drain，否则会降低 deadlock 测试强度。
- 回滚：回退本记录对应 commit 即可；这些变更不涉及用户数据或协议。
- 依赖：Node >=22、Rust 1.98.0、Python PTY、本地 mock Harness，以及锁定的 Grok mirror checkout。
