# 开发 profile 自举与启动预检

> 记录时间：2026-08-24 21:19:19 +0800
> 操作者/agent：Codex
> 状态：completed

## 目标与背景

修复 `scripts/start-new-chat.sh` 在新机器或未初始化 `$DSH_HOME` 时因缺少
`grok-tui` profile 而退出的问题。建立可重复、幂等的开发 profile 初始化链路，
让启动脚本和真实 E2E 复用同一套 Harness 路径、profile、Node/pnpm 和 TypeScript
构建预检，避免依赖某台机器此前遗留的 profile。

## 设计契约和复用依据

- 对应长期计划章节：M0 治理/基线、M1 contract/projection/effects 的外部启动边界、
  8 H2/H3 的 host/profile 生命周期、10 测试和验收矩阵。
- Grok source path、commit、SOURCE_REV：不涉及 Grok 源码或 UI 组件。
- 复用等级：不适用；复用现有 `scripts/real-e2e.sh` 的本地三包 link 约定。
- DSH contract delta：不改变协议、session、Intent、Effect 或 wire method；只规范
  Harness profile 的初始化和启动前诊断。

## 计划修改范围

- `scripts/dsh-tui-common.sh`：共享仓库/Harness/DSH_HOME/profile/pnpm 解析和预检函数。
- `scripts/setup-dev-profile.sh`：幂等构建并一次性 link 三个本地 TypeScript 包。
- `scripts/start-new-chat.sh`：默认使用项目专属 profile，启动前自动自举并预检。
- `scripts/real-e2e.sh`：复用共享解析和 profile 自举，缺失 profile 时提前给出可操作错误。
- `README.md`：补充首次启动、自动自举、环境变量和自定义 profile 说明。
- `docs/TESTING.md`：统一真实 Harness 的 setup/check/run 流程和干净环境要求。
- `docs/EXTERNAL_DSH_PLUGIN.md`：统一开发 profile 的推荐入口和发布 profile 的边界。
- 本记录文件：回写实际修改和验证结果。

## 风险、回滚和预期验证

- 风险：首次运行可能在仓库 `node_modules`、TypeScript `lib` 和 `$DSH_HOME/profiles` 写入
  开发依赖；profile 初始化只操作选定 profile，不修改 Harness checkout。
- 风险：用户通过 `DSH_TUI_PROFILE` 指定已有非本项目 profile 时，默认拒绝覆盖，需显式
  `DSH_TUI_PROFILE_ALLOW_UPDATE=1`。
- 回滚：恢复两个启动脚本及文档，删除新增共享/初始化脚本；不删除用户已有 profile。
- 预期验证：`bash -n`、帮助/非法参数、无 profile 的临时 `DSH_HOME` 自举、真实
  `--hello`、真实 E2E 脚本的静态检查、`cargo fmt --all -- --check`、`git diff --check`。

## 实际修改

- 新增 `scripts/dsh-tui-common.sh`，集中解析仓库根、相邻/显式 Harness checkout、
  Node/pnpm、`DSH_HOME`、项目 profile 和本地 TypeScript 构建产物。
- 新增 `scripts/setup-dev-profile.sh`。首次运行按需执行 workspace install、每次启动构建
  当前 TypeScript 包，并用
  一次 `dsh plugin add` link protocol、server、embedded；重复运行保持幂等。
- 默认 profile 改为项目专属 `dsh-pager-grok-dev`。已有非本项目 profile 默认拒绝
  覆盖，只有显式设置 `DSH_TUI_PROFILE_ALLOW_UPDATE=1` 才允许更新；profile 名称先做
  路径安全校验。
- `scripts/start-new-chat.sh` 默认自动执行 profile 自举，新增 `--skip-setup`；`--check`
  继续保证不创建 session，并在进入 backend 前得到明确的 profile 诊断。
- `scripts/real-e2e.sh` 复用同一套路径/profile helper；`DSH_TUI_INSTALL_LOCAL=1` 调用
  统一 setup，未请求安装时先验证 profile，而不是等 Node backend 输出深层堆栈。
- README、验证策略和外置插件文档统一为 setup → check → run 流程，说明 `$DSH_HOME`
  是仓库外机器状态、CI 应使用临时 home、发布包与开发 link 的不同边界。
- 在真实 `$HOME/.dsh` 创建了项目专属 `dsh-pager-grok-dev` profile，只包含本仓库三个
  TypeScript 包的本地 link；未改 Harness checkout 或现有其他 profile。
