## 目标与背景

用户提供的 Grok Build 实际截图中，右侧使用标准 scrollbar，顶部右侧只显示
`38K / 500K` context usage。当前 DSH UI 虽然接入了正确的 smooth scrollbar
primitive，却把 Grok 的可选 timeline sidebar 硬编码为开启，导致两个及以上
turn 时右侧 gutter 被 timeline rail 替代；顶部还额外展示连接、模型、队列和
running/idle 状态。

## 设计契约和复用依据

- Grok source commit：`19d42e35c07a9c9244f03f6df0c4c353f970d4f9`；
  SOURCE_REV：`7d67deacbeb1c1093fdb4f9bcbfab2630e18a6aa`。
- `xai-grok-shared/src/ui_config.rs` 明确
  `UiConfig::SHOW_TIMELINE_DEFAULT = false`，timeline 是 opt-in，并注明它会
  “in place of the scrollbar”；本批修正 DSH appearance 默认值，复用等级 A1。
- `xai-grok-pager/src/app/agent_view/render.rs` 仍决定 scrollbar/timeline 的
  排他顺序；默认关闭 timeline 后，多 turn overflow 也应绘制 scrollbar。
- 顶部继续复用已移植的 `AgentStatusBar + context_bar`，但只 push `context`
  item，保持 Grok 截图中的右对齐 compact usage 和 hover 行为。
- 不改变 Harness `contextPressure` 真源、token 格式、scroll offset、stable ID、
  generation、RPC 或 wire contract。

### 文件

### 摘要

- `GrokAppearanceSnapshot` 新增 `show_timeline` 并按上游
  `UiConfig::SHOW_TIMELINE_DEFAULT` 固定为 `false`；runtime 不再把
  `rail_width` 的开关硬编码为 true。
- 修复第二层 rail gate：`render_transcript` 只在 layout 实际分配
  `timeline_width > 0` 时调用 `compute_rail`。此前即使宽度为 0，两个 turn
  仍能算出 rail 并吞掉 scrollbar。
- 默认多 turn overflow 现在继续使用上一批已接入的 Grok smooth scrollbar；
  timeline renderer 和 opt-in 排他路径仍保留，等待后续 settings seam。
- 顶部 `AgentStatusBar` 只 push context item，移除 connection/model/queue 和
  running/idle item；context 缺失时右侧留空，普通态/hover 态仍保持相同宽度。
- semantic buffer 测试增加 header 单行断言，并把两 turn 场景改为验证
  scrollbar 存在、timeline hit region 不存在。
