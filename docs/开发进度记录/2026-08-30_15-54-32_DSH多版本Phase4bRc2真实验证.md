## 目标与背景

为 `apiproxy-v1` 建立与根 workspace/node_modules 隔离的 DSH 0.1.1-rc.2 npm
组合，使用真实 rc.2 CLI/profile/ApiProxy 跑通 install、build、hello/list/load 和
PTY。完成后按 D-R2 对 rc.8 做同 family 的尽力验证。rc.2 是 Phase 4 的阻塞
门禁；若必须修改 Rust wire 才能通过，立即停止并登记。

## 设计与范围

- canonical 版本、tag、commit、package manager、family/profile schema 均来自
  `compat/dsh-support.json`；rc.2 继续保持 `candidate`，本批只证明其晋级前置条件，
  `supported` 状态留给 Phase 6 cold-install 全证据完成后修改。
- 新建 `compat/fixtures/dsh-0.1.1-rc.2/`，package/lock 只含 npm 可解析的 rc.2
  依赖；不读取根 workspace 的 DSH override，也不在主 manifest 加 rc.2 类型。
- fixture bundle 从 rc.8 legacy patch 恢复 ApiProxy profile composition，但移除
  已不存在的项目 projection-recovery 插件；TUI plugin 通过 profile-local
  `createRequire` 调用 Phase 4a 的 runtime guard，并实例化 `ApiProxyV1Backend`。
- 测试 profile 使用项目专用名 `dsh-pager-grok-apiproxy-v1-rc2-e2e`，位于本批
  新建的 `/tmp` DSH_HOME。不会读取或修改 `~/.dsh`、用户 profile、sessions 或
  credentials；临时路径和清理结果在完成时回写。
- rc.8 复用同一 fixture 逻辑在另一临时 DSH_HOME/独立 install 中验证；如连续
  两次因版本差异无法推进或出现不成比例分叉，按 D-R2 将其降为 unsupported，
  否则保持 maintenance。

## 风险与回滚

- 风险：npm rc.2 的 profile loader 与 legacy rc.8 patch 有局部差异；只在 fixture
  composition/adapter-local normalization 吸收，不复制 gateway、不改变 wire。
- 风险：pnpm link 可能回落到根 module graph；验证脚本必须打印并断言 CLI、
  ApiProxy 与 package manager 的真实版本/解析路径位于 fixture/profile。
- 风险：PTY 会写占位凭据；只在临时 DSH_HOME 中运行并在退出后删除整棵临时树。
- 回滚：revert 本批即可删除隔离 fixture；临时 profile 随临时 DSH_HOME 删除，
  不影响既有 alpha profile。

## 实际修改

- 新增独立 nested pnpm workspace，直接依赖的 DSH 包全部 exact
  `0.1.1-rc.2`，lockfile 不含 `workspace:`、`link:` 或 alpha 版本。fixture 的
  CLI 与 ApiProxy 由 npm 安装，未经过根 workspace override。
- 从 legacy Embedded patch 恢复无浏览器/HTTP 的 ApiProxy profile composition；
  移除当前仓库已不再发布/维护的 projection-recovery 插件，保留 storage、
  workspace、directory picker、file reference、agent preset 和 ApiProxy host。
- fixture plugin 使用 profile-local `createRequire` 解析
  `dsh-host-apiproxy.toFetchHandler`，再实例化 Phase 4a `ApiProxyV1Backend`；
  fileReferences/commands/resolveAgent extensions 延续 legacy 公开接缝。
- `check-build.mjs` 断言 DSH CLI 与 ApiProxy 的 exact 版本及真实解析路径位于
  fixture；同时导入 built adapter/core 和 runtime guard。
- `run-e2e.sh` 固定 profile 子进程使用注册表声明的 pnpm 11.7.0，在 fresh
  `/tmp` DSH_HOME 初始化 project-named profile，依次执行 hello/list/dashboard/
  load/PTY，退出后带路径 guard 清理临时 home。
- fixture 与临时 profile 分别维护 reviewed build-script allowlist：真实 PTY/
  subprocess 所需的 node-pty、koffi、dsh-subprocess-local 允许执行，其他已审阅
  no-op 依赖显式拒绝；没有放宽根 workspace 策略。
- runner 可通过 `DSH_COMPAT_VERSION=0.1.0-rc.8` 在独立临时安装中复用同一
  adapter/profile composition，用于 D-R2 maintenance 验证；持久 fixture 的
  package/lock 仍只 canonicalize rc.2。
