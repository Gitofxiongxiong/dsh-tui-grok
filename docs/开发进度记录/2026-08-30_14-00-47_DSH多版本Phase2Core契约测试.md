## §16.1 现有 14 场景审计表

| 契约项 | 现有覆盖 | 结论/本批动作 |
|---|---|---|
| hello 与 generation | `requires hello...`、`rejects a mismatched...`、`rejects stale generations...` | 已覆盖：hello 前置、版本拒绝、generation 递增/陈旧拒绝；不重复。 |
| attach/detach/subscribe | `attaches a follower...`、`folds an all-session...`、无效 payload 用例 | 已覆盖 attach/detach、未知 session、session/all subscribe；不重复。 |
| history/load barrier | `attaches a follower...`、`keeps follower content buffered when history fails` | 已覆盖成功 flush、失败保持、无关 session 过滤；不重复。 |
| mux/host buffering | `attaches a follower...` 同时验证 follower mux 缓冲、global mux 与 session-scoped host 投递/过滤 | 已覆盖当前设计：mux 过 history barrier，host 不进 history buffer 而按订阅范围投递；不重复。 |
| control-plane baseline/replay | `folds an all-session control stream and can resume retained records` | 已覆盖 baseline-required、store fold、resume replay；不重复。 |
| request abort | `cancels an executing bridge request when the connection is disposed`、`dispatchUnary` signal 用例 | 已覆盖 request signal 透传与 dispose abort；不重复。 |
| respond fingerprint 与 at-most-once | `deduplicates accepted interaction replies but permits correction after rejection` 覆盖拒绝后纠正及不同 fingerprint 拒绝 | **部分覆盖**：缺少相同 fingerprint 的并发/完成后重放只调用 backend 一次；新增 1 个用例。 |
| reconnect/dispose 资源清理 | generation 用例覆盖 attachment reset；serve 用例覆盖 bridge dispose | **部分覆盖**：缺少 follower/mux/host signal 在 repeated hello 与 dispose 时均被 abort 的显式证据；新增 1 个用例。 |
| unsupported capability | 无；core 尚无 enforcement | 按 D-P2/任务约束显式跳过，Phase 5 再实现并测试。 |

## 风险、回滚和依赖

- 风险：异步生成器未开始迭代时无法观测 signal；测试在断言前等待一个 event-loop
  turn，并只观测 signal 状态，不依赖内部私有字段。
- 风险：并发 respond 测试若提前 resolve 会掩盖 in-flight 去重；用手动 promise
  gate 保证第二次调用发生在首个 backend response 完成前。
- 风险：server invariant 测试原先依赖真实 Cordis registry；替换 fake 时保留重复
  注册错误和 disposer 删除注册的契约，不修改生产 invariant 或组装层。
- 回滚：本批独立测试 commit 可整体 revert，无运行时或数据迁移。
- 依赖：当前 Vitest/TypeScript workspace、Rust toolchain、已存在的真实 E2E 脚本。

## 实际修改

- 在既有 14 个 `gateway.spec.ts` 场景上只新增 2 个缺口用例：
  - 相同 interaction fingerprint 在并发 in-flight 与完成后重放时复用同一 promise，
    backend 总调用次数保持 1。
  - repeated hello 与 dispose 分别 abort follower/mux/host 的旧/当前 signal，并清空
    fake backend attachment。
- 定向 `rg` 发现 `tests/invariant.spec.ts` 预先存在 Cordis/DSH 直接 import，与本批
  明确验收冲突；改用结构化 fake registry，保留原 service inject、重复注册和
  disposer 断言。未修改 server invariant 生产源码或 `index.ts` 组装层。
- gateway 既有 14 个用例和断言未修改；新增后 gateway 为 16 个用例。
- unsupported capability 按约束未实现、未添加假失败测试，留给 Phase 5。
