## 风险、机器状态与回滚

- protocol/server 当前是内部 workspace 包；若作为独立公开包会把 source-only alpha
  peers/workspace spec 带入 tarball。先审计实际组合边界：可以作为“内部 bundle
  输入候选”pack，但绝不伪称 registry-installable；正式公开候选必须通过相同
  no-local/no-alpha gate。若与 D-R10 的 runtime 内嵌策略冲突，以发布 runtime/CLI
  实际 cold graph为准，并在本记录说明取舍。
- cold 演练目录将在 `/tmp/dsh-pager-release-candidate.*` 下用 `mktemp -d` 创建，
  本记录先于执行登记。它是本批要求交付的证据产物，成功后保留并只报告精确路径；
  不写真实 `~/.dsh`，不读真实凭据。
- 所有 registry 操作仅限 `npm view`/install read。禁止 `npm publish`、dist-tag、
  git push、GitHub Release、workflow dispatch；脚本中也不得包含可误触发的发布调用。
- rc.2 status 是本批最后变更；任一 cold/PTY/pack/§21 项失败则保持 candidate。
  发布前可 revert 本批 commit；真实发布后的回滚只能由维护者使用 deprecate/dist-tag
  或新 patch，不能覆盖已发布版本。

## 实际修改与验证结果

### 发布单元、版本与直接 `npm pack`

- 只读 `npm view` 确认 `@dsh-pager-grok/cli@0.1.0`、
  `native-linux-x64-gnu@0.1.0` 和旧 `runtime@0.1.0` 均已存在，不能覆盖不可变
  version。此次包含多版本 CLI/profile/runtime 新功能，故 Cargo workspace、root、
  CLI、两个 runtime、protocol/server/embedded 与五个平台 manifest 统一提升为
  `0.2.0`；`Cargo.lock` 同步，pnpm lock 经 non-frozen 更新后再次 frozen 验证。
- 新增 `pack-release-candidates.mjs`，对 host native、private protocol、private server、
  public `runtime-apiproxy-v1` 与 public CLI 逐个执行直接 `npm pack`。每包都校验版本、
  三份 license/notice、关键文件、private/public 边界以及无 `link:`、`workspace:`、
  alpha spec。CLI 五个平台 optional dependencies 与 server→protocol 也在源码 manifest
  内写成 exact `0.2.0`，不依赖 pnpm pack 的隐式转换。
- public 发布图只有 native、`runtime-apiproxy-v1`、CLI；protocol/server 是 runtime
  内嵌前的 bundle 输入，保持 private，不 publish。现有 `runtime` 继续是
  controllers-v2/alpha source-only 开发单元。该取舍严格采用 §13.2/D-R10 的 family
  runtime 方案，没有简化成含 alpha 条件依赖的单一公开 runtime。
- `pack-native.mjs` 支持显式 destination；protocol/server pack 补齐完整 lib 与 licenses；
  `verify-cli-pack.mjs` 也改为直接 npm pack。公开依赖门禁与 cold graph 均证明没有
  alpha、workspace 或 sibling Harness checkout 泄漏。

### CLI cold profile 与迁移策略收口

- CLI 只在 `DSH_PAGER_DEV_MODE=1` 接受 `DSH_PAGER_RUNTIME_SPEC`，避免生产启动被环境
  注入本地 spec。新增 canonical profile build policy merge：补齐 runtime 所需 native
  allowBuilds、替换 DSH 自动生成的占位值，同时保留用户已经明确写出的 true/false。
- 自动 family runtime 解析仍是正式发布后的生产路径。演练发生在 publish 之前，
  registry 不可能已有 `runtime-apiproxy-v1@0.2.0`，因此 rehearsal 明确按 D-R10 的
  “安装或开发配置提示”路径：用 packed CLI 的 canonical helper 初始化 family profile，
  从本地 runtime tarball 安装并写 ownership，之后所有 hello/list/load/doctor/PTY 都走
  正常 warm launcher。没有读取真实 credentials，也没有写真实 `~/.dsh`。
