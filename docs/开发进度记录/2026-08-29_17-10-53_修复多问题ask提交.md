## 目标与背景

DSH `ask_user_question` 可在一个 request 中携带多个问题，当前
Grok question card adapter 只渲染 `questions.first()`，并只提交第一问。
Host 会以 `bad-response` 拒绝不完整答案；TUI gateway 又会把
`accepted: false` 的尝试留在 at-most-once 缓存中，导致后续修正答案
被误报为 `already-resolved (-32003)`。

本批在独立 worktree 分支 `fix/multi-question-ask` 中完成修复，不触碰
主 worktree 的未提交变更。

## 设计契约和复用依据

- 对应长期计划章节：M7.3 approval/question modal，M9.5 effect duplicate semantics，P11 stale interaction。

  mirror commit `19d42e35c07a9c9244f03f6df0c4c353f970d4f9`，SOURCE_REV
  `7d67deacbeb1c1093fdb4f9bcbfab2630e18a6aa`。
- 复用等级 B：保留已 vendor 的 Grok question card 绘制，多问题页签、草稿和
  DSH 批量答案组装放在 adapter/runtime seam；不修改 vendor 文件。
- DSH 真源：request id + generation 仍是交互身份；只在所有问题都有
  有效答案后发送一次 `tui.respond`。
- gateway 仅对 Host 已接受的响应保留 resolved tombstone；Host 逻辑拒绝后
  允许修正同一 request。

- 风险：multi-select 与 freeform 必须保持 DSH schema；本批先覆盖当前
  Grok card 能表达的单选和无选项自由文本，不伪造 multi-select UI。

## 实际修改

- `crates/dsh-pager-grok-ui/src/views/interaction.rs`
  - question adapter 按索引投影任意一问，并在多问题标题中显示 `1/3` 进度；
  - 新增逐问本地草稿，只有全部问题显式作答后才组装完整 `answers` 数组；
  - 保持单问题、选项 label、自由文本和鼠标噪声过滤的原有协议语义。
- `crates/dsh-pager-grok-ui/src/runtime.rs`
  - 每个 pending request 初始化独立逐问草稿；Tab/BackTab 循环切换并恢复各问选择；
  - 数字键、Enter 和鼠标双击完成当前问题，自动跳到下一未答问题，最后一次性提交；
  - 单问题仍保持数字键/Enter 立即提交，快捷提示按单问/多问语义显示。
- `packages/dsh-tui-server/src/gateway.ts`
  - `accepted: false` 只表示 Host 拒绝该 payload，不再留下 completed tombstone；
  - exact concurrent payload 仍复用同一 promise，只有 `accepted: true` 才永久去重。
- `packages/dsh-tui-server/tests/gateway.spec.ts`
  - 覆盖同 request 首次 `bad-response`、修正 payload 后再次提交成功的回归场景。
- `crates/dsh-pager-bin/tests/mock-server.mjs`
  - 增加确定性的三问题 `multi question smoke` fixture，并严格拒绝缺项答案。
- 未修改 Grok vendor；多问题状态与批量协议仍位于 DSH adapter/runtime seam。
