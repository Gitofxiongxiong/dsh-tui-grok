# CI 构建精确 Harness Alpha 依赖

> 记录时间：2026-08-30 10:50:27 +0800
> 操作者/agent：Codex
> 状态：completed

## 目标与背景

- Harness alpha 升级分支接管 `main` 后，GitHub Actions run `33288750616`
  的三平台 Rust job 正常，`verify-ts (ubuntu)` 在 `pnpm run verify:ts` 失败。
- 原因是 `pnpm-workspace.yaml` 为未发布的 Harness `0.1.2-alpha.1` packages 使用
  `link:../deepseek-harness-latest/...`；本机存在该精确 checkout，干净 GitHub
  runner 没有，因此 TypeScript 无法解析 `dsh-session/types`、`dsh-brand`、
  `dsh-invariants`、`cordis` 等模块。
- 目标是让 CI 明确获取、校验并构建同一 Harness tag，而不是依赖 runner 隐含
  目录、退回 rc.8/0.1.1，或删掉类型检查。

## 设计契约和复用依据

- Harness 真源固定为官方仓库 tag `dsh-v0.1.2-alpha.1`、commit
  `cd5ef8148158c3a752a658978873241fdf8e2bbc`，与本分支完整验证使用的 checkout
  完全相同。
- CI 在当前仓库相邻路径 `../deepseek-harness-latest` shallow clone 该 tag，
  以精确 commit 断言防止 tag/clone 漂移；这与 workspace link contract 对齐。
- 先在 Harness checkout 执行 frozen install 和 `build:lib:host`、
  `build:lib:client`，再安装/验证本仓库；不修改或重新发布 DeepSeek packages。
- Harness 自身的 package-manager guard 固定 pnpm 11.7.0，本项目固定
  pnpm 11.20.0；CI 在各自的 install/build 阶段使用显式的 Corepack 版本化调用，
  不让任一仓库跳过自身版本契约。
- 本批次属于 CI/发布基础设施，Grok source/revision、复用等级和产品 TUI 不适用。

## 计划修改范围

- `.github/workflows/ci.yml`
  - 为 `verify-ts` 增加精确 Harness clone、commit 校验、frozen install 和 host/client
    library build，并在 Harness 与本项目阶段分别调用 pnpm 11.7.0 和
    11.20.0。
- `docs/开发进度记录/2026-08-30_10-50-27_CI构建精确HarnessAlpha依赖.md`
  - 记录失败、实现、验证、PR/CI 和回滚。
- 不在范围内：产品源码、package 版本、pnpm override/lockfile、发布 workflow、
  Rust job、Harness 仓库内容、npm publish 和用户配置。

## 风险、回滚和依赖

- 风险：Harness build 增加 CI 时间和网络流量；使用 depth-1 tag clone，正确性优先，
  后续可在独立记录中增加只读 cache。
- 风险：只 clone 不 build 会留下缺失 `lib/*.d.ts`；显式执行 host/client 两套构建。
- 风险：官方 tag 被移动；精确 commit 断言会 fail closed，不静默消费新内容。
- 回滚：revert 本记录对应提交；这会恢复已确认会失败的 clean-runner 状态，
  不影响产品或远端 legacy 回滚点。

## 实际修改与验证

- `.github/workflows/ci.yml` 的 `verify-ts` job 在本仓库 install 前新增：
  - depth-1 clone 官方 `dsh-v0.1.2-alpha.1` 到 workspace sibling
    `../deepseek-harness-latest`，并断言 HEAD 精确等于 `cd5ef814...`；
  - 在 Harness 目录用 `corepack pnpm@11.7.0` frozen install 并依次构建
    host/client libraries，使 workspace link 的 JS/type exports 在本项目
    install 前就绪；
  - 回到本项目目录用 `corepack pnpm@11.20.0` 执行项目 frozen install 和
    原有 `verify:ts`。
- 保持三平台 Rust job、项目 `pnpm install --frozen-lockfile` 和
  `pnpm run verify:ts` 原样；没有放宽或跳过类型/pack 测试。
- `python3` + PyYAML 解析 `.github/workflows/ci.yml` 并断言
  `jobs.verify-ts` 存在：通过。
- `git diff --check`：通过。
- 修改前远端 run `33288750616` 的 Rust ubuntu/macos 已通过，`verify-ts`
  因缺少 sibling Harness links 失败；Windows Rust 尚在运行。该 run 固定为
  失败复现证据，不重跑旧提交伪装成功。
- PR 首次 run `33288989145` 已证明精确 tag clone 和 commit 断言通过，
  但 Harness install 被其自身版本 guard 拒绝：当时 CI 使用了本项目的
  pnpm 11.20.0，Harness 明确要求 11.7.0。在独立临时 clone
  `/tmp/harness-ci-repro.BZFRQP` 复现同一报错，据此改为两阶段切换。
- 进一步验证发现 `corepack prepare --activate` 在当前 Corepack 0.35.0 下仍可由
  已选中的 pnpm shim 执行错误版本；改用目录对齐的
  `corepack pnpm@<exact>` 后，临时 clone 的 pnpm 11.7.0 frozen install、
  `build:lib:host` 和 `build:lib:client` 全部通过。
