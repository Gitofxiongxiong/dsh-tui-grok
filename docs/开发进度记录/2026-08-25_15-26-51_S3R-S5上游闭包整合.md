## 本轮目标

1. 将 S3R 的 `EntryRenderer` / `BlockRenderer` 重基为上游形态，使 entry renderer 直接面向 ratatui `Buffer` 输出，并接管 entry chrome、group header、timestamp、裁剪及选择几何。

4. 保留 DSH 的 stable ID、ordered blocks、mode/running/finished/timestamps 等宿主语义，不把 Grok pager runtime 引入生产链。
5. 在 S3R–S5 稳定后另建 S6 主记录，再修改 host revision/range/borrow seam；S6 不混入本记录提交。

## 合同与非目标

- 生产 transcript 不再自行定义 group header、timestamp、entry gutter/chrome 和 block dispatch 视觉规则。
- renderer 必须以稳定 entry identity 工作；动态 thinking/tool 状态不能依赖展示文本作为身份。
- 窄宽度、顶端裁剪、Unicode 宽度、running animation、hover/selection 等关键分支必须有测试。
- 不移植 Grok runtime、数据库、网络、shell/process worker、clipboard 或媒体加载副作用。
- 不为追求文件行数相同而引入 DSH 无法表达、且无可见行为收益的依赖。

## 风险与回滚

- 风险：上游 renderer 依赖完整 pager state，直接照搬会把 Grok runtime 传染到 DSH；通过 renderer-neutral DTO 和纯 Buffer seam 隔离。
- 风险：当前工作区存在跨阶段未提交改动；每次修改前后使用 `git diff --check`、定向测试和 source manifest 检查确认没有误伤。
- 风险：视觉闭包可能改变 snapshot；仅接受能由上游基线或 DSH 宿主合同解释的变化。
- 回滚：本轮只通过小步补丁修改计划范围内文件；不使用 destructive git 命令。若某个上游分支无法无 runtime 移植，保留当前稳定实现并在本文档登记缺口。
