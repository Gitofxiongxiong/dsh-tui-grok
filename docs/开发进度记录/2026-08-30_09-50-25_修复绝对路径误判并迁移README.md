## 目标与背景

- 修复 prompt 以 Unix 绝对路径开头时被当成未知 slash command、因而无法提交给模型的问题。
- 把主分支 `/home/leo/code/dsh-pager-grok/README.md` 的用户导向首页迁入 Harness `0.1.2-alpha.1` 分支。
- 主分支 README 同时引用 `README.en.md` 和 `docs/assets/readme/welcome.png`；为避免坏链接，一并迁移配套英文页和图片。
- 用户要求分析并实施修复；主目录保持只读。

## 设计契约和复用依据

- 对应长期计划章节：Grok prompt/slash 交互状态机、DSH effect 路由、用户可见 TUI 验证门禁。
- Grok 对应源码：vendored `slash::parse_invocation` / `slash::analyze_input`；保持其 picker、模糊匹配和本地 command dispatch 不变。
- 复用等级：B（slash 输入分类的窄适配）和文档同步。
- DSH-neutral seam：普通 prompt 仍走 `SubmitPrompt`；已登记的 local/Host slash command 仍走现有 local action 或 `ExecuteCommand`。
- command name 已有合同是 ASCII 字母数字、`-`、`_`；包含额外 `/` 的 token 不可能是合法 local/Host command，应作为普通 prompt。
- 保留未知但语法合法的 `/plna` 错误和 command list refresh，不把命令拼写错误静默提交给模型。

## 开始前证据

- 行为来自共同历史提交 `8d1d2aa`，不是 Harness alpha 升级引入的回归。

## 风险、回滚和依赖

- 过宽回退会让 `/plna` 等拼写错误进入模型；用现有 command name grammar 限定回退范围。
- `/tmp` 既可表示路径也符合命令名语法，仍保持 unknown command；本批次只消除 token 内含路径分隔符的明确误判。
- README 主分支文字仍区分 npm `0.1.0` 与当前源码；迁移后必须避免把尚未发布的 alpha 适配描述成 npm 已发布能力。
- 回滚：revert 本记录对应的单个提交；不涉及会话、profile 或持久数据迁移。

## 实际修改

- `slash.rs` 增加 `is_command_candidate`，复用 local/Host registry 共享的
  ASCII command-name grammar；`/home/leo/...`、`/usr/bin/env`、`/路径/项目`
  不再是 command candidate，`/plan` 和 `/plna` 仍是。
- `runtime.rs` 在 local/Host/unknown-command dispatch 前应用该分类；不符合
  command token 语法的 leading-slash 文本走原有 `submit_prompt`，不改
  `SubmitPrompt` effect 和 receipt 语义。
- 回归测试覆盖绝对路径、Unicode 路径、合法 command、语法合法但拼错
  的 command、单独 `/` 和普通 prompt。
- 从只读主分支原样迁入用户导向的 `README.md`、`README.en.md`
  和 `welcome.png`；两份 README 都明确区分已发布 npm `0.1.0`/Harness
  rc.8 与当前源码 Harness `0.1.2-alpha.1` 的启动边界。
- `welcome.png` 与主分支源文件 SHA-256 均为
  `f751799628c32870f1d68279b844e36cbc53c776767a3dc441dab8644e4036c0`。
- `src/slash.rs` 属于已登记的 Grok B/A1 wrapper；门禁发现的
