# 官方斜杠命令分流修复

> 记录时间：2026-08-29 11:32:52 +0800
> 操作者/agent：Codex
> 状态：completed

## 目标与背景

当前 Grok TUI 能通过 `commands/list` 展示 DSH 官方斜杠命令，但提交时只区分
“TUI 本地命令”和“普通 prompt”：所有 Host 命令都会回落到 `session.prompt`。
因此 `/permission danger-full-access`、`/plan off` 等文本被作为用户消息发送给
模型；`Ctrl+O` 的 YOLO 路径也把 `/permission ...` 编码成 prompt。

本批接通 DSH 官方 `CommandRuntime.execute`，把本地命令、Host 命令、未知斜杠
输入和普通对话分流。目标是修复整个 Host command 类别，而不是给
`/permission` 增加特例。

## 设计契约和复用依据

- 对应长期计划章节：2.3（DSH 唯一真源）、2.4（Intent/Effect/Receipt）、
  2.7（wire 向后兼容）、M5（slash/input）、M10（真实后端验收）。
- DSH 真源：
  - `deepseek-harness/packages/interaction/commands/src/index.ts::CommandRuntime.execute`：
    只执行当前 Agent scope 中已注册命令，返回 `CommandExecution | undefined`，并
    记录 `command/run`/`command/done`，命令文本和结果不进入模型历史；
  - `deepseek-harness/packages/client/ui-commands/src/client/service.ts::execute`：官方
    Web 客户端通过 `remote.commands.execute(sessionId, line, images)` 分发；
  - `deepseek-harness/packages/interaction/commands/README.zh.md`：未知斜杠命令必须
    拒绝，不能降级成模型 prompt；命令生产者（例如 `/plan [message]`）可以在
    handler 内显式安排真正的模型输入；
  - `session.prompt` 当前实现只负责 durable user message，不再解析 command。
- Grok source path、commit、SOURCE_REV：继续复用现有 Grok slash controller、
  completion、prompt editor 和 status 呈现；不修改 vendor。mirror commit
  `19d42e35c07a9c9244f03f6df0c4c353f970d4f9`，SOURCE_REV
  `7d67deacbeb1c1093fdb4f9bcbfab2630e18a6aa`。
- 复用等级：A0/A1（现有 Grok slash UI/键盘状态机不变）；B（controller 向
  runtime 返回 Host command 分类）；C（DSH `commands/execute` wire、DTO、effect、
  receipt 和 authoritative projection 收敛）。
- DSH-neutral seam：新增 `UiIntent/UiEffect::ExecuteCommand`；view 仍不持有
  `RpcTransport`，Host command 名册来自 `CommandDescriptor`。

## 风险、回滚和依赖

- 风险：TUI server 目前只有 command list extension；execute 必须沿用相同 Agent
  resolver，不能用 session.prompt 或在客户端猜测权限/Plan 状态。
- 风险：`CommandExecution | undefined` 的 wire 需要明确 matched/unmatched，不能把
  JSON 中缺失 `value` 当成功；TUI extension 将 unmatched 规范化为显式 `null`。
- 风险：Host command handler 可异步执行；请求取消信号应绑定 gateway connection
  lifetime，连接重置/销毁后中止等待，不能留下无主调用。
- 风险：命令 catalog 在请求与执行间可能变化；Host execute 是最终准入真源，
  unmatched 必须保留草稿并刷新目录，而不是回落 prompt。
- 回滚：回滚本记录对应单一 commit；协议新增方法向后兼容，旧 server 会返回
  method-not-found 并由 typed effect 显示 unavailable，不涉及 session 数据迁移。
- 预期验证：TypeScript protocol/server tests；Rust protocol/effect/runtime/slash tests；
  workspace check/test、manifest/fixture/parity 检查、PTY；真实 DSH profile 验证
  permission/plan/unknown command 不产生模型消息；用户可见状态通过 ttyd + xterm.js +
  Playwright 与 Grok 同职责命令输入/状态呈现对比。

- 摘要：
  - stdio 协议和 TUI server 新增 `commands/execute`；server 继续复用官方
    `CommandRuntime` 与 session-to-Agent resolver，把 `undefined` unmatched 规范为
    `{ matched: false, execution: null }`，连接 dispose/reset 会中止仍在运行的命令；
  - Rust 新增 typed `CommandExecuteValue` / `CommandExecution` / result DTO、loader API
    与 `UiIntent/UiEffect::ExecuteCommand`。`Ctrl+O` 的 `/permission` 也改走同一 execute
    plane，不再伪装成 `session.prompt`；
  - prompt 提交统一先处理 Grok-derived 本地命令，再按当前 `commands/list` 精确匹配
    Host 命令，只有非斜杠普通文本进入 `session.prompt`；未知、malformed 或 catalog
    已失效的 `/...` 保留草稿、显示错误并刷新目录，绝不降级为模型消息；
  - Host command completion 按 session/generation/request guard 收敛，成功或业务错误
    显示官方 result text；unmatched/transport error 保留输入。普通 command 不建立
    first-prompt pending，permission 只有 matched + success 才等待权威 projection；
  - `slash.rs` 只增加 Host 精确分类 seam，继续复用既有 Grok controller、completion、
    prompt editor、状态栏和菜单；source manifest hash 已同步。
