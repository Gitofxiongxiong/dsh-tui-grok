- 风险：符号链接可指向不存在目标或不应共享的可写状态。修复只处理源

  `DSH_HOME` 拥有。

  PTY 启动前对目标可解析性 fail closed。

## 实际修改

- 根因：`setup-dev-profile.sh` 通过 pnpm `link:` 安装的 package 在 profile
  `node_modules` 中是相对符号链接。例如源 profile 的
  `@dsh-pager-grok/tui-embedded` 原始目标为
  `../../../../../code/dsh-pager-grok/packages/dsh-tui-embedded`，从
  `/home/leo/.dsh/profiles/...` 解析为 `/home/leo/code/...`；`cp -a` 将同一
  原始文本保留到 `/tmp/dsh-pager-real-e2e.*/profiles/...` 后，却解析为
  不存在的 `/tmp/code/...`。Harness 因此在 TUI server 启动前遇到
  `MODULE_NOT_FOUND`，`pty-smoke.py` 的首屏等待最终表现为
  `SessionLoaded` 超时。
- `scripts/real-e2e.sh` 仍先完整复制 profile，以保持配置和 Harness 运行时
  写入隔离；随后用 NUL 分隔遍历源 profile 的符号链接，将隔离副本中
  对应链接重建为指向源链接当前规范目标的绝对链接。每个重建链接在
  启动 PTY 前再次 `realpath` 比较，无法解析或目标不等时非零退出。
- 未改默认 45 秒超时、`pty-smoke.py`、`SessionLoaded` 判定、profile
  manifest、凭据/session/storage 隔离策略或任何产品/wire/UI 实现。
- 诊断副本保留在 `/tmp/dsh-profile-link-diagnostic.q51vvx`，只包含专用
  profile wiring 的临时副本，不含凭据、session 或 storage；
  `real-e2e.sh` 自身的 `/tmp/dsh-pager-real-e2e.*` 已按原有 trap 清理。
