# DSH 多版本 Phase 2 协议与 core 去耦

> 记录时间：2026-08-30 13:53:25 +0800
> 操作者/agent：Codex
> 状态：completed

## 目标与背景

执行 `docs/DSH_MULTI_VERSION_COMPATIBILITY_PLAN.md` §19 Phase 2 的第一批：
让 TypeScript TUI 协议镜像与 server core 不再依赖 DSH 类型，以项目自有 brand、
session event 投影和中性 unary method catalog 固定现有 TUI v1 wire 行为。

## 设计契约和复用依据

- 对应长期计划章节：§6、§16.1、§19 Phase 2。
- 基线：`docs/compat/DSH_TUI_V1_BASELINE.md` 的 55 unary + 5 control +
  5 notification 目录；`TUI_PROTOCOL_VERSION` 保持 1。
- D-P2-2：`TuiBackend.call` 收紧为 `TuiUnaryMethod`，gateway 在既有 `api`
  分类分支内用 `isTuiUnaryMethod` 显式收窄；失败复用 `TuiMethodNotFoundError`。
- D-P2-3：保留协议包 `./invariant` 伴生插件的物理位置与运行时注册逻辑，
  仅改用项目自有结构化 context/installer 类型。这是对方案“转移到
  adapter/runtime 边界”措辞的最小实现，达成协议包零 DSH 依赖的验收目标，
  不改变 profile 加载行为。
- D-P2-4：`TuiSessionEvent` 只描述 core 已消费的 `{ type: string; seq: number }`
  与 JSON 透传字段；不增加运行时校验，Rust reducer 仍是事件判别真源。
- 复用等级：A0（现有 wire catalog、codec、gateway 行为原样保留）。

## 风险、回滚和依赖

- 风险：自有 brand 若引入运行时逻辑会改变 codec；实现限定为原字符串的纯 cast。
- 风险：SPI 收紧可能暴露未收窄的 core 调用点；仅在既有 `api` 守卫内补类型谓词，
  不改变可达错误路径。
- 风险：删除 peer/dev dependency 后 invariant 测试不能再实例化 Cordis；测试改用
  最小结构化 fake，并继续验证重复注册与 disposer 行为。
- 回滚：本批独立 commit 可整体 revert；不需要迁移数据或 profile。
- 依赖：当前 workspace 安装结果、Rust stable toolchain、Python 3。

## 实际修改

- 新增项目自有 `Branded`/`SessionId` 与零成本 brand 工厂；codec、ids、types
  不再导入 DSH brand/session。
- 新增 `TuiSessionEvent` 透传投影。首轮 typecheck 证明 core 除 `type` 外还直接
  消费 `seq`，因此最小投影细化为 `{ type: string; seq: number } &
  Record<string, unknown>`；未增加运行时校验。
- invariant 伴生插件改用自有结构化 context/installer 类型，注册调用和 no-op
  installer 不变；测试以结构化 fake 验证相同的重复注册契约。
- unary catalog 改用 `TUI_UNARY_METHOD_SET`、`TuiUnaryMethod`、
  `isTuiUnaryMethod`，并导出 control/notification 目录；旧三个名称均以
  `@deprecated` 别名保留。
- `TuiBackend.call` 与 `dispatchUnary` 收紧为 `TuiUnaryMethod`；gateway 在既有
  `api` 分支显式收窄，失败复用既有 method-not-found 路径。
- 删除协议包的四组 DSH/Cordis peer/dev dependency；lockfile 只把该 importer
  化简为 `{}`。
- 未改 method 字符串、wire 形状、错误 kind、协议版本、bridge 实现或 Rust 源码。
