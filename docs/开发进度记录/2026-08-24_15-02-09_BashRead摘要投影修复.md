# Bash / Read 摘要投影修复

> 操作者/agent：Codex
> 状态：completed

## 目标与背景

Harness 的 Bash presenter 把模型生成的一行说明放在 terminal card
`description` 中，DSH Web 在该字段缺失时还会从调用参数的
`description`/`command` 回退。当历史事件没有 presenter view 时，当前
Execute adapter 直接放弃投影，导致 Bash 的说明丢失。

Read presenter 会提供 `Read <path>` title，DSH Web 的通用回退也会从
`path`/`file_path` 取摘要。当前 transcript 却把单个 Read 也替换为
`Read 1 file` 分组标题，路径说明被覆盖。

## 设计契约

- Bash 仍由已移植的 Grok `ExecuteToolCallBlock` 负责展示；本批只补齐
  DSH-neutral adapter 的数据优先级。
- Bash 命令/说明优先用 presenter view，view 缺失或字段为空时从
  JSON arguments 回退；不修改 Harness 或协议 DTO。
- Read 单条折叠分组显示 `Read · <path>`；连续多条 Read 仍保留 Grok
  风格的计数分组，展开后每条仍显示 presenter title。
- 参数回退只用于展示，不改变 session 真源、stable ID、generation 或
  fold state。

## 风险与回滚

- arguments 可能是流式中间态或旧版非 JSON 字符串；解析必须失败安全，
  不得影响已有 presenter 路径。
- 单 Read 分组标题需保留 group hit target，不能破坏双击展开与零高度
  成员投影。
- 回滚本记录对应的单一 commit 即可恢复。

### 摘要

- Execute adapter 现在先使用 Harness terminal/generic presenter；当 view 缺失、
  terminal `description` 为空或 generic content 没有说明时，从 JSON
  arguments 的 `description` 回退，命令从 `command` 回退。
- 无 view 的 `bash`/`pwsh` 历史事件也能投影为同一 Grok
  `ExecuteToolCallBlock`，折叠行显示说明，展开后仍显示命令与输出。
- Read 摘要按 DSH Web 的稳定优先级从 arguments 的
  `path`/`file_path`/`url` 取值，然后才回退到 structured result path 和
  presenter title。
- Read 分组分类在 view/result 缺失时可用稳定工具名 `read` 回退。
  单个 Read 折叠行改为 `Read · <path>`，不再用 `Read 1 file` 吞掉路径；
  多个连续 Read/Search/Web 仍使用原有计数分组。
- 新增 4 个 adapter/renderer 契约测试，覆盖无 view、空 presenter
  description、presenter 优先级以及 Bash/Read 一行摘要。
