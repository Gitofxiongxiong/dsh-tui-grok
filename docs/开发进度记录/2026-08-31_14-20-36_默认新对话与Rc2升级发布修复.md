# 默认新对话与 rc.2 升级发布修复

> 记录时间：2026-08-31 14:20:36 +0800
> 操作者/agent：Codex
> 状态：completed

## 目标与背景

- 用户发现当前 `main` 与 npm `0.2.0` 又恢复成“无参数优先打开最近会话”，而不是
  Grok Build 对齐的“无参数新建会话”。审计确认旧修复位于本地未发布分支提交
  `bd7fdec`，没有进入 `main`、`v0.2.0` 或远端分支。
- 用户本机从 npm `0.2.0` 切换到 DSH `0.1.1-rc.2` 后，旧 profile 虽然 metadata
  对齐，但缺少 `@deepseek-ai/dsh-base`、hoisted linker 和关闭 peer 自动安装的
  安装布局；旧 doctor 只检查 metadata，可能显示正常而真实 hello 失败。
- 发布恢复过程中还发现 npm 12 的 `npm view ... version --json` 会返回单元素数组，
  旧 registry gate 只接受字符串；本地候选演练又可能让 pnpm 把 CLI 的同版本
  native 可选依赖解析到 registry 旧包，造成“候选演练实际运行旧二进制”。
- 本批目标是把旧的默认新对话逻辑以当前多版本架构重新合入 `main`，修复 rc.2
  profile 升级，并把上述问题加入可重复发布门禁。不会在本批执行 push、npm
  publish、dist-tag 或 GitHub Release。

## 设计契约和复用依据

- 对应长期计划章节：产品启动器、family profile migration、多版本发布候选冷安装
  与真实 PTY 门禁。
- Grok source path、commit、SOURCE_REV：本批不修改 Grok vendored UI/source
  revision；会话启动语义复用已审计旧提交 `bd7fdec`。
- 复用等级：会话选择和 CLI argv 属现有 Rust host 适配层；profile/runtime 修复属于
  产品 launcher 与发布基础设施，不改 DSH wire 或 Grok UI。
- 无会话旗标严格等价于新建；恢复必须显式使用 `--resume/-r`、
  `--continue/-c`、兼容 `--session` 或 TUI `/resume`。
- `--resume` 无 id 只选择当前工作目录下最新的非空顶层会话；没有匹配历史时失败，
  不静默创建会话。
- profile 可启动证据必须同时包含 ownership metadata、`dsh-base` bundle、hoisted
  linker、`autoInstallPeers: false`、完整 allowBuilds 和可解析 family runtime。
- legacy/不完整 profile 使用 rename backup 后重建；sessions、credentials 和旧
  projection cache 不迁入新 profile，也不删除。

## 风险、回滚和依赖

- 风险：默认值变化会让依赖隐式恢复的内部 smoke 失去历史 fixture；这些 smoke
  改为显式恢复 `session-mock`，并新增独立默认新会话断言。
- 风险：迁移不完整 profile 会触发一次目录改名；保留时间戳 backup，且只复制
  pager settings 白名单。回滚代码不会自动删除 backup。
- 风险：候选版本与 registry 已发布版本相同时，pnpm 可能为 CLI 嵌套解析旧 native；
  local-tarball 演练通过 workspace override 强制使用同批 host native。
- 风险：开发机环境中的 `DEEPSEEK_API_KEY` 会让凭据层正确标记为不可写，从而让
  PTY 的写入用例误超时；真实 PTY 调用在隔离 home 下移除该环境变量。
- TypeScript 完整验证依赖精确 DSH alpha source graph；按 CI 契约克隆
  `dsh-v0.1.2-alpha.1`/`cd5ef814...` 到 sibling checkout，仅作为外部构建依赖，
  其 Git 工作树保持干净。

## 实际修改

- Rust 默认 `SessionChoice::New`；新增 `Recent`，以及 `--resume [id]`、`-r`、
  `--continue`、`-c` 和 `--resume=<id>`。当前目录无历史时显式恢复返回清晰错误。
- binary integration 覆盖裸启动 `session-created`、显式 session id、当前目录最近
  会话和 strict no-history；interaction/queue/lifecycle fixture 改为显式恢复。
- launcher 生成/修复 profile 时强制 `@deepseek-ai/dsh-base`、
  `nodeLinker: hoisted` 和 `autoInstallPeers: false`；doctor 把 layout evidence 纳入
  profile 健康状态。metadata 对齐但布局不完整的 profile 也会备份重建。
- registry gate 同时接受 npm 11 的 JSON 字符串与 npm 12 的单元素字符串数组；
  多元素数组仍 fail closed。
- release rehearsal 新增候选 native override、打包后二进制默认新会话断言、legacy
  profile 升级备份、base/runtime/policy 断言、sessions/credentials sentinel、真实
  rc.2 doctor/hello 与隔离 PTY。registry 恢复模式不应用本地 native override。
- 真实 E2E/rc.8/rc.2 PTY 移除调用者的 `DEEPSEEK_API_KEY`；测试写入只发生在临时
  `DSH_HOME`。
- 中英文首页保留 npm `0.2.0` 的显式 `--new` 安装示例，并清楚区分已发布旧行为与
  当前源码/下一 patch 的新行为；产品 launcher/测试文档同步当前契约。
