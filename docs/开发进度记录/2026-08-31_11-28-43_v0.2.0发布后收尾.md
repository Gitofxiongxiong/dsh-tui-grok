## 验证结果

- 七个公开 package 的官方 registry 只读核验：全部 `version/latest/release-candidate` 为
  `0.2.0`，全部存在 `dist.integrity`；五个平台 native 与 CLI 均存在
  `dist.attestations.url`，runtime 符合已批准的 bootstrap 例外。
- 最终 release rehearsal：
  `env -u DEEPSEEK_API_KEY npm_config_registry=https://registry.npmjs.org/
  DSH_RELEASE_REGISTRY_VERSION=0.2.0 DSH_RELEASE_CLI_TARBALL=<official-cli-tarball>
  npm exec --yes --package=npm@11.13.0 -- bash -c
  './scripts/rehearse-release-candidate.sh'`：通过。
  - cold audit：24 个 dependency-graph package、15 个精确 DSH package；
  - `doctor --release`：17 个精确 non-optional registry dependencies 可用；
  - hello/list/load、warm/offline hello、PTY login/resume/terminal restore：通过；
  - `/tmp/dsh-pager-release-candidate.ZV349R/result.json`：`passed`。
- 环境诊断记录：
  - 本机默认 `npm@12.0.2` 对精确 version 的 `npm view ... --json` 返回单元素数组，公开
    CLI 的 registry gate 只接受字符串，首次 rehearsal 因此产生 false negative；固定到
    正式 workflow 的 `npm@11.13.0` 后通过。这是后续新版本需单独处理的兼容性事项。
  - 第二次 rehearsal 继承本机会话的 `DEEPSEEK_API_KEY`，使专门验证 `/login` 输入框的
    PTY 用例按设计失败；最终仅在隔离子进程移除该变量后通过，未读取或修改真实凭据。
- annotated `v0.2.0` Tag peeled commit：

  非 prerelease，发布时间 `2026-08-31T03:27:29Z`。
- `node scripts/check-dsh-support.mjs`：通过，3 个 registry versions、22 个 runtime exact
