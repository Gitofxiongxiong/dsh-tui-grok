# 视觉验证范围扩展：修复 PTY 跨块解析

## 时间

- 开始：2026-08-29 22:22:00 +0800
- 结束：2026-08-29 22:37:29 +0800
- 状态：实现与 PTY 门禁完成；浏览器像素门禁同主记录受外部网络策略阻塞

## 背景

Harness 升级后的长流 PTY 验证间歇失败。Grok `GROK_SCROLL_LOG` 证明单个滚轮
事件已按合同立即产生 `-1` 行，但失败画面出现裸露的 `[25;77H`。开启飞行日志仅
改变输出分块便可通过，说明产品状态机正常，验证器的轻量终端模型在 ANSI CSI
恰好跨两个 `read()` 时丢弃了前半段 ESC，并把后半段误画为正文。

同一实现也会丢弃跨块 UTF-8 字符与未闭合 OSC，因此稳定帧、中文文本和 marker
判断都可能随 PTY 分块随机漂移。

## 修改范围

- `scripts/pty-smoke.py`
- `scripts/pty-stream-scroll.py`
- `docs/开发进度记录/2026-08-29_22-22-00_视觉验证范围扩展-修复PTY跨块解析.md`

## 必须保持的合同

- `AnsiScreen.feed()` 在任意输入分块下与一次性 feed 得到相同 screen。
- 未闭合 CSI、OSC 与 UTF-8 尾字节保留到下一次 feed；完整控制序列仍不进入正文。
- 不引入第三方终端模拟器，不改变 PTY 操作步骤或产品代码。
- prompt 文本先形成稳定帧再单独发送 Enter；精确一行滚动以同一 marker 的
  屏幕行坐标差判断，不依赖视口边缘是否恰好露出前一个 marker。
- 定向覆盖 cursor CSI、OSC 和中文 UTF-8 的所有拆分点，并重跑 smoke、ESC、
  stream-scroll 与浏览器视觉验证。

## 回滚

本范围使用独立 Git commit；普通 `git revert` 即可恢复原验证器。

## 结果

- `AnsiScreen.feed()` 现在保留跨 `read()` 的 CSI、OSC 与 UTF-8 尾块；对 cursor
  CSI、OSC、中文 UTF-8 的 40 个两段拆分点及逐字节 feed 定向校验均与一次性
  feed 一致。
- stream 验证先等待 prompt 稳定帧，再聚焦并清空 transition 字符，文本稳定后
  单独发送 Enter；精确滚动改为比较同一 marker 的屏幕行坐标。
- full PTY smoke 与 ESC parity 通过；stream-scroll 连续两次通过，分别报告
  `marker=235 row=14->15, down_reports=24, tail=30->66` 与
  `marker=235 row=14->15, down_reports=24, tail=29->66`。
- 全部门禁结束后的最终连续复跑再次通过，两次均为
  `marker=235 row=14->15, down_reports=24, tail=30->67`；tail 的新增末端 marker
  不改变同 marker 精确一行移动的断言。
- 产品 Rust/TypeScript 未因验证器修复而改动。浏览器 `.xterm` 尚未取得，阻塞证据
  与完成条件记录在主升级记录，故本记录不把 PTY 结果等同于视觉 parity。
