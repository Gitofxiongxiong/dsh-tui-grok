# Phase 6 发布前 ApiProxy 矩阵产物修复

> 记录时间：2026-08-30 18:12:56 +0800
> 操作者/agent：Codex
> 状态：completed

## 目标与背景

- PR #4 CI run `33305693707` 已通过三平台 Rust、TS/contracts、fixture、
  support 和 registry dependency gates。
- 动态矩阵中 rc.8 job `99242151232` 与 rc.2 job `99242151269` 在
  各自 exact fixture install 后以相同错误失败：从原始
  `packages/dsh-tui-server/lib/core/gateway.js` 导入时找不到
  `@dsh-pager-grok/tui-protocol`。
- CI artifact 只恢复了 protocol/server 的 `lib` 目录，没有也不应携带
  主 workspace `node_modules` peer 解析链。
- `@dsh-pager-grok/runtime-apiproxy-v1` 已是 Phase 5d 建立的可发布 family
  runtime；其 bundle 内已将 protocol/server 间引用改为相对路径，适合作为
  ApiProxy 矩阵的可复用构建产物。

## 计划修改范围

- rc.8/rc.2 fixture 的 `index.js` 与 `check-build.mjs` 改为从
  `packages/dsh-pager-runtime-apiproxy-v1/lib/server` 取 adapter/core，仍将
  `createRequire(import.meta.url)` 显式传入 adapter，保证 DSH 运行时依赖来自
  各自 exact fixture，而不是 runtime workspace 的 alpha override。
- 两个 `run-e2e.sh` 的 skip-build 产物存在性断言同步为 family
  runtime 路径。
- `.github/workflows/ci.yml` 的复用 artifact 改为携带
  `packages/dsh-pager-runtime-apiproxy-v1/lib`、CLI lib 和 native binary；不打包
  `node_modules`。

## 风险与回滚

- 不能改成直接使用 runtime `server-entry.js`：该入口的 `createRequire`
  以 runtime 自身为基准，本地 workspace 中可能受 alpha override 影响。fixture
  保留现有组装层，只切换至 bundle 内的 self-contained adapter/core。
- 必须在隔离主 workspace `node_modules` 的条件下复核 rc.8/rc.2，防止
  再次被本机 symlink 隐藏。隔离时仅临时改名，trap 必须原样恢复；不删除
  任何 profile/session/credential。
- 本批可单独 revert；PR 全绿前不合并，不执行 npm
  publish/dist-tag、Tag 或 Release。
