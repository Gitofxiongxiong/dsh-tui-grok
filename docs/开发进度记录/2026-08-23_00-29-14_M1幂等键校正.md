# M1 幂等键校正

> 记录时间：2026-08-23 00:29:14 +0800
> 操作者/agent：Codex `/root`
> 状态：completed

## 目标与背景

让 `UiContext` 携带一次用户操作的 request identity，使同一 operation 的重试复用稳定 dedupe key，而相同 prompt 的两次独立提交不会被错误合并。

## 设计契约和复用依据

- 对应长期计划章节：2.4、M1.5、M1.6；同一 effect 重试必须幂等，不同用户意图不得静默去重。
- Grok source：不涉及 vendor；DSH-neutral seam 在 `crates/dsh-pager-grok-ui/src/effects.rs`。
- 复用等级：C。

## 计划修改范围

- 文件：`crates/dsh-pager-grok-ui/src/effects.rs`、`crates/dsh-pager-grok-ui/src/runtime.rs`、本记录。
- 预期行为：`UiContext` 支持显式 operation id；concrete sink 暴露 effect dispatch 校验；completed operation 按稳定 operation key 去重；新增测试覆盖同操作重试与相同文本独立提交。
- 不在范围内：protocol、vendor、DSH loader 语义和 M0 baseline 文件。

## 风险、回滚和依赖

- 风险：公开 neutral API 增加一个 operation id 字段；fallback runtime 必须为每次提交生成新 id。
- 回滚：回退本次单独 commit，不影响 M0/M1 主提交。

## 实际修改

- `UiContext` 增加显式 `request_id`，并提供 `for_operation` 构造器；pending context 仍由 concrete sink 分配新 id。
- `compile_intent` 对显式 operation 使用 `action:request_id` 稳定 dedupe key；fallback 每次新提交继续获得新 id，避免相同 prompt 被错误合并。
- `DshEffectSink::dispatch_effect` 对外暴露 neutral effect dispatch，completed operation 以完整 `OperationKey` 去重，允许显式 operation 重试收敛。
- 增加相同文本不同操作与显式 operation identity 测试。
