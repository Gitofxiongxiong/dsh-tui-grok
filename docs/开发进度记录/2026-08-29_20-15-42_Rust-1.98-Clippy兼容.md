## 目标与背景

前一批修复 Node 24 stderr flood、source manifest 和 PTY `/login` 稳定帧后，`scripts/e2e.sh` 在 Rust 1.98.0 all-features clippy 继续暴露：

- `dsh-pager` 核心 host 中 8 个可机械合并的 nested `if`；
- 未修改的 upstream `xai-grok-markdown` source 触发 `question_mark` 和 `unnecessary_sort_by` 两个新 lint。

目标是在不改变 host 语义、不修改 upstream markdown source 和测试的前提下，恢复 Rust 1.98 all-features clippy 门禁，然后完整跑通 E2E + full PTY。

## 设计契约和复用依据

- 对应长期计划章节：M0.4/M0.5 baseline/clippy，2.5 依赖和源码契约，M9/M10 完整门禁。
- Grok source path、commit、SOURCE_REV：markdown source 来自 mirror commit `19d42e35c07a9c9244f03f6df0c4c353f970d4f9`（SOURCE_REV `7d67deacbeb1c1093fdb4f9bcbfab2630e18a6aa`）。
- 复用等级：C（DSH host 真源内部的等价语法改写）；A1 wrapper config（markdown Cargo manifest 的定点 lint allow）。
- host 只将 `if { if ... }` 合并为 let-chain/boolean-chain，不改变 return、mutation、ordering 或 identity 契约。
- vendor markdown 只在已经是本地 wrapper 的 `Cargo.toml` 中 allow `question_mark` 和 `unnecessary_sort_by`；不改任何 upstream `.rs` source，并同步 SOURCE_MANIFEST vendored hash/本地修改描述。
