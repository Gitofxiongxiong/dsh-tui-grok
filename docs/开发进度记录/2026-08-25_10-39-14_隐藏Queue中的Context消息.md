# 隐藏 Queue 中的 Context 消息

> 记录时间：2026-08-25 10:39:14 +0800
> 操作者/agent：Codex
> 状态：completed

## 目标与背景

Shift+Tab 切换会话模式时，DSH approval service 会把审批策略变更以
`placement: context` 注入 agent inbox，供下一次 model step 消费。当前
Grok UI 把 authoritative queue snapshot 里的所有 placement 都算入 Queue
pane，因而向用户显示 `The approval policy changed ...`。

用户要求该 context 通知不得显示。Prompt 提交固定 `steer` 的语义
保持不变。

## 设计契约和复用依据

- 对应长期计划章节：2.2 交互契约、2.3 DSH 真源、M7 queue/interactions。
- Host contract：`context` inbox item 在被 agent claim 前对用户不可见；
  UI 不得删除或改写 authoritative snapshot。
- Grok source/revision：不修改 vendor；沿用现有 Grok queue pane 和 stable-ID
  selection，只在 DSH-neutral queue view 边界加 placement 可见性策略。
- 复用等级：B/C seam（Grok pane/state machine 保留，DSH placement 语义由
  adapter/view seam 过滤）。
- 新增 DTO/Intent/Effect：无。稳定 queue item ID、revision 和 host authority 不变。

## 风险、回滚和依赖

- 风险：渲染过滤与选择/快捷提示过滤不一致，产生空 pane 或隐形可操作项。
- 缓解：在 queue view 定义单一可见性 helper，runtime/parity 复用；补充
  mixed/context-only 渲染和 selection 测试。
- 回滚：回退本记录对应的 queue view/runtime/parity 变更，即恢复展示
  snapshot 全部 item。
- 依赖：现有 `QueuePlacement` typed contract、mock Harness 和 TTYD/Playwright
  浏览器终端验证链路。
