## 目标与背景

- 用户确认按源码分析方案执行：把 Grok Build 的上下滚动核心完整移植到 DSH Grok TUI，
  解决流式输出期间滚轮回弹、卡顿和难以到达底部的问题。
- 当前已经原样 vendor Grok `input/mouse.rs`，事件循环也接入输入优先和 scroll clock；
  但生产 transcript 仍由本地 `TranscriptViewportState`、DSH Fenwick 高度索引、
  `DshScrollbackHost` anchor/materialization 三套状态共同决定位置。
- 当前 streaming partial revision 会丢弃 rich entry 缓存，并通过 complete-document seam
  重渲染整篇 Markdown；这没有使用 Grok `MarkdownContent` 的增量 renderer/checkpoint/cache。
- 现有 PTY 用 80 个 wheel-down report 强制越过尾部，不能证明真实有限手势能到达底部。

## 风险、回滚和依赖

- 上游 state 源码与 Grok block/appearance/selection/media 类型耦合较深；适配必须集中在窄
  投影边界，不允许为了编译而另写一个简化滚动状态机。
- UI mirror 必须按稳定 ID 增量更新；若每个 token 全量重建 entries，会重新引入卡顿并破坏
  structural anchor。
- 流式文本可能不是严格 append；adapter 需要检测前缀，append 时 push chunk，非前缀时只
  重建该 block，并在 finish/generation 切换时清理缓存。
- 回滚为回退本记录对应单一提交；不修改持久化会话、协议版本或后端数据。

## 实际修改

- 新增 `scrollback_adapter/state.rs`，按上游
  `scrollback/state/{mod,layout,nav}.rs` 的状态闭包做 B 类 host adaptation：
  - 一个 `GrokScrollbackState` 独占 `scroll_offset / total_height / viewport_height /
    follow_mode / viewport_anchor / sticky rows`；
  - `prepare_layout` 在一个有界 settle pass 内恢复稳定 entry anchor、解析可见高度、clamp 或
    follow 尾部，并只在 pass 完成后捕获新 anchor；
  - 复制 Grok 的 landing-at-bottom 与 fully-clamped overscroll-follow 区别，以及按真实
    viewport/sticky/overlap 计算的 page、half-page、`g/G` 导航。
- `runtime.rs` 删除本地 `TranscriptViewportState`、独立 `scroll_anchor`、主 transcript 的
  第二次 prepare 和 child 的 `scroll_top/follow` 平行状态；主会话和 subagent 详情现在都由
  `GrokScrollbackState + MouseScrollState` 驱动，child scroll clock 也进入 event-loop deadline。
- `host_pane.rs` 把生产 viewport 改为一次 `prepare_viewport` 加
  `visible_lines_prepared` 消费：手动停驻只测可见区及向下 8 个 entry，follow 向上预热 3
  页，rich cache 保留窗口为 128 个 entry；不再在视口上方逐帧测量后把 max-scroll 推来推去。
- `render/markdown.rs` 新增基于上游 `StreamingMarkdownRenderer` 的
  `StreamingMarkdownContent`；append revision 只 push 新 suffix，width/theme 原位更新，
  finish 用一次完整 render 收口，非前缀修正只重建对应 block。`host_pane` 按稳定
  `(entry_id, block_index)` 保存缓存，rich entry 离开可见窗口时不丢 Markdown checkpoint。
- `materialize_entry.rs` 接入 top-level Assistant/Thinking Markdown cache；保留 complete-render
  fallback 给非流式/未缓存 block，不改变 DSH protocol/generation/identity 真源。
- `app.rs` 把 PageUp/PageDown、Ctrl+U/Ctrl+D、`g/G` 变成 Grok scroll action；页面步长不再
  写死 8 行。`scripts/pty-stream-scroll.py` 把 80-report flood 改为 24 个逐 report、逐帧 pump
  的有限手势，并要求额外 fully-clamped report 恢复 follow。
- 更新 `SOURCE_MANIFEST.md`、`GROK_SCROLLBACK_CLOSURE_PLAN.md`、
  `GROK_TUI_TRANSCRIPT_SURFACE.md` 和 `TESTING.md`，固定来源、closure boundary、缓存和
  验收合同。未修改 Grok vendor 文件本体，也未改变 DSH wire fixture。
