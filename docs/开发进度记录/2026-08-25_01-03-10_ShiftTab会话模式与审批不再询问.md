# Shift+Tab 会话模式与审批不再询问

> 记录时间：2026-08-25 01:03:10 +0800
> 操作者/agent：Grok
> 状态：completed

## 目标与背景

pager 的 Shift+Tab 目前只在本地翻转 `PromptMode`（queue/steer），底部
`Shift+Tab:mode` 文案来自 Grok CycleMode，但没有写入 DSH 的沙箱/审批/计划旋钮。
用户要求固定三档会话模式，并把投递模式锁成 steer，不再给用户选择。

三档：

- `normal`：sandbox `workspace-write`，approval `ask`，plan off
- `plan`：sandbox `read-only`，approval `ask`，plan on
- `danger-full-access`：sandbox `danger-full-access`，approval `never`，plan off

normal 的 ask 审批卡增加「本对话不再询问」：允许当前动作，并把本会话切到
`danger-full-access`。

## 设计契约和复用依据

- 对应长期计划章节：2.2 交互契约、2.3 DSH 真源、M7.3 approval、adapter 接线。
- Grok CycleMode（Normal / Plan / Always-Approve）映射到上面三档；Always-Approve
  不伪造 DSH 审批 outcome，只切换会话级 `approval: never` + `danger-full-access`。
- 复用等级：
  - 协议/server applyMode：C（DSH 真源写入）
  - Grok `ActionId::CycleMode`、permission card：B（保留按键/卡片几何，增加一档选项）
  - queue/steer 切换：删除用户可选 UI，提交固定 `steer`（idle 时 DSH steer 仍会开 turn）
- DSH-neutral seam：`tui.setSessionMode` 为 TUI 自有方法；view 不直接 RPC。
- 新增 DTO/Intent/Effect：`TuiSetSessionModeParams/Result`、`UiIntent::SetSessionMode`、
  `UiEffect::SetSessionMode`、`SessionModeId`。
- 审批 outcome 仍只有 `allowed-once` / `rejected`；不再询问是第二次 `tui.setSessionMode`。

## 风险、回滚和依赖

- 风险：plan 插件未挂载时 `/plan` 失败，必须中止整档切换以免半应用；mock
  与真实 Harness 投影形状不一致导致 UI 显示错误档。
- 缓解：applyMode 原子失败即停；客户端以 `plan` + `permissions` 投影为准，
  事件 fold 作后备；mock 同步发出这两项投影。
- 回滚：恢复 Shift+Tab → TogglePromptMode 与两选项审批卡。
- 依赖：现有 tui-server 进程内 `ctx.agents` / `ctx.commands` / `ctx.approval`；
  不改 Harness ApiProxy。
