# Shift+Tab 依赖注入修复

> 记录时间：2026-08-25 09:27:26 +0800
> 操作者/agent：Codex
> 状态：completed

## 目标与背景

真实 DSH profile 中，用户聚焦输入框并按 `Shift+Tab` 后，
`tui.setSessionMode` 返回 JSON-RPC `-32603`，详情为
`cannot get property "agents" without inject`。按键和 RPC 路由已正常触发，
失败点是 `tui-server` 调用 `createApiRemoteAgentResolver()` 时直接读取
`ctx.agents`，但插件只声明了 `apiProxy` 注入。该解析器的冷会话路径
还会直接读取 `ctx.sessions`。

## 设计契约和复用依据

- 对应长期计划章节：2.3 DSH 真源、2.4 Intent/Effect/Receipt、M7 交互。
- Grok source path、commit、SOURCE_REV：不适用；本次仅修正 DSH host Cordis 组合边界。
- 复用等级：C（DSH 插件注入和服务解析）。
- 保持现有 `tui.setSessionMode` 协议、模式循环和 Grok UI 不变，不新增平行真源。

## 计划修改范围

- 文件：

- 不在范围内：修改会话模式语义、UI 样式、Harness ApiProxy 或其他插件。

## 风险、回滚和依赖

- 风险：新增必需注入后，缺少 `agents`/`sessions` 的不完整 profile 会在
  插件挂载时显式失败，而不是在首次 Shift+Tab 时延迟失败；完整
  `dsh-base` profile 已提供两项服务。
- 回滚：恢复原 `inject` 列表并移除对应回归测试。
- 依赖：`@deepseek-ai/dsh-api-remotes` 的 Agent 解析器合同；现有 embedded
  profile 中的 Agent/Session 服务。

## 实际修改

- 文件：
  - `packages/dsh-tui-server/src/index.ts`
  - `packages/dsh-tui-server/tests/gateway.spec.ts`
  - 本记录
- 摘要：
  - 将 `tui-server` 的必需注入从仅 `apiProxy` 补齐为
    `apiProxy` / `agents` / `sessions`，与 `createApiRemoteAgentResolver()` 的
    直接服务读取一致。
  - 将插件集成测试从仅验证 `tui.hello` 扩展为：真实 Cordis
    上下文挂载 `apiProxy` / `agents` / `sessions`，然后通过 stdio
    JSON-RPC 执行 `tui.setSessionMode`，断言从 `danger-full-access` 循环至
    `normal` 并写入 sandbox/approval 事件。该测试在原注入列表下会
    复现 `cannot get property "agents" without inject`。
