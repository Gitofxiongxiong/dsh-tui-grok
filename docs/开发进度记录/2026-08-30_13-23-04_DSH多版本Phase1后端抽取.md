## 目标与背景

落地 `docs/DSH_MULTI_VERSION_COMPATIBILITY_PLAN.md` §19 Phase 1：以当前 alpha.1
`TuiHarnessBridge` 的公开方法为现实基线，抽取 `TuiBackend` SPI，让
gateway/dispatch/serve 只依赖中性 port，不改变 history、stream、interaction、
control-plane 或 transport 行为。

## 设计契约和复用依据

- 对应长期计划章节：多版本方案 §5、§7.1–§7.2、§9.1、§19 Phase 1；D2/D5/D6。
- 边界契约：`TuiGateway` 仅持有 `TuiBackend`；`index.ts` 继续作为具体
  controllers-v2 组装层；当前类继续保留所有公开方法和语义。
- 现实签名优先差异 1：方案 §7.1 的 `call` 参数是未落地的
  `TuiUnaryMethod`；现有 `TuiHarnessBridge.call` 是 `method: string`。按本批约束使用
  `string`，不提前执行 Phase 2 的 `ApiProxyMethod` 重命名。
- 现实签名优先差异 2：方案示例的 `respond` 返回
  `TuiRespondResult`；现有公开签名是
  `Promise<{ accepted: boolean; reason?: string }>`。SPI 保留可选 `reason`，不缩窄现实合同。
- `BridgeMuxEnvelope` 当前由具体 bridge 定义。为防止 SPI 反向依赖
  adapter，将中性 envelope 定义为 `TuiMuxEnvelope`，并在 `bridge.ts` 保留
  `BridgeMuxEnvelope` 类型别名以维持现有导出兼容。
- Grok source path、commit、SOURCE_REV：不适用；不修改 Rust/Grok UI。
- 复用等级 A0/A1/B/C/D：D（DSH-neutral server port 与 controllers-v2 adapter metadata）。

## 风险、回滚和依赖

- 风险：过早缩窄 `method` 或 `respond` 返回类型可能产生隐性行为/诊断丢失。
- 缓解：逐项复制当前公开签名，使用 TypeScript `implements` 和无强转 fake 作静态证据。
- 风险：新增 `info` 若在构造时执行任何上游检测会改变启动。
- 缓解：`info` 只由已有 `HARNESS_VERSION` 和常量字面量组成，无 I/O、无 service 访问。
- 回滚：单独 revert 本批 interface extraction commit，恢复 core 对具体 bridge 的类型引用。
- 依赖：只使用现有 `@dsh-pager-grok/tui-protocol` 类型，不新增包。

## 实际修改

- `packages/dsh-tui-server/src/backend.ts`：新增 DSH-neutral `TuiBackend`、
  `TuiBackendInfo`、`TuiCapabilities` 和 `TuiMuxEnvelope`；方法签名与现有
  bridge 公开面对齐。
- `packages/dsh-tui-server/src/bridge.ts`：`TuiHarnessBridge implements TuiBackend`，
  增加 `controllers-v2` / `HARNESS_VERSION` / schema 2 / 14 项全 true capability
  的常量 metadata；`BridgeMuxEnvelope` 保留为中性 envelope 的兼容别名。
- `gateway.ts`、`dispatch.ts`、`serve.ts`：只将构造/调度/组装参数类型改为
  `TuiBackend`，所有运行时调用次序、buffer、abort 和 dispose 逻辑保持不变。
- `packages/dsh-tui-server/src/index.ts`：保留全部原导出，新增四个 SPI 相关类型导出；具体 bridge 仍只在组装层实例化。
- `packages/dsh-tui-server/tests/gateway.spec.ts`：`FakeBridge` 显式实现
  `TuiBackend`，收紧 respond/envelope 签名，删除 `as unknown as` 转换；没有改变任何期望值、matcher 或场景断言。
- 未修改 runtime 行为、`ApiProxyMethod`、bridge 内部拆分、Rust 代码、manifest、lockfile、CI 或 profile/scripts。
