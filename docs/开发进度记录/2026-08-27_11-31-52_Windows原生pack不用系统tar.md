# Windows 原生 pack 用 Node 列 tarball，不依赖系统 tar

> 记录时间：2026-08-27 11:31:52 +0800
> 操作者/agent：main agent
> 状态：completed

## 目标与背景

`release-native` 的 `pack win32-x64` 在 `pack native tarball` 步以退出码 2 失败。
其它四平台 pack 成功。`scripts/pack-native.mjs` 的 `auditTarball()` 在 win32 上
仍调用系统 `tar -tvf` 列 `.tgz`。Windows GHA 的 `tar.exe`（bsdtar / Git tar）
解 gzip 要再 spawn `gzip`，Node `spawnSync('tar')` 找不到可用 gzip 时失败。
本批次改为用 Node `zlib` 解析 ustar，不再依赖 PATH `tar`/`gzip`。

## 设计契约和复用依据

- 对应计划：PRODUCT_PLUGIN_LAUNCHER.md v2 原生包 pack 审计（许可证 + Unix 可执行位）。
- I6 要检查的仍是 packed tarball 内容，不规定必须调用系统 `tar`。
- Grok source path、commit、SOURCE_REV：不适用。
- 复用等级：D（发布脚本，不复制 Grok）。

## 计划修改范围

- 文件：
  - `scripts/pack-native.mjs`
  - 本进度记录

  mode 含 owner/group/other 执行位。npm pack `--json` 的 `filename` 在
  Windows 绝对路径下也能定位到 tarball。

## 风险、回滚和依赖

- 风险：ustar 解析漏 GNU long-name → 本仓库 native 路径都短于 100 字节，
  npm pack 用 `package/` 前缀，足够。
- 回滚：还原 `pack-native.mjs`。
- 依赖：Node 内置 `zlib`；不新增 npm 包。

## 实际文件与摘要

- `scripts/pack-native.mjs`：`auditTarball` 改为 `gunzipSync` + ustar 头解析；
  不再 `spawnSync('tar')`。非 win32 用 mode `& 0o111` 断言可执行位。
  同时兼容 npm 10 `pack --json` 数组和 npm 12 按包名索引的对象；
  `filename` 支持绝对路径。
- 本进度记录。

## 验证

- 用 GNU tar 打的 fixture `.tgz`：`listGzipTarEntries` 读到
  `package/bin/dsh-pager` mode `755`，三份许可证齐全。
- `node scripts/pack-native.mjs --id linux-x64-gnu --skip-build`：exit 0，
  产物含 `bin/dsh-pager` 与 LICENSE-MIT/APACHE/NOTICE。
- 同一 tarball 再解析：`package/bin/dsh-pager` 为 `0755`。
