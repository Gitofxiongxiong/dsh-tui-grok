## 目标与背景

当前默认 TUI 把 Harness 的 `approval/requested` 与普通 question 一起放进居中的
`ModalWindow`，并用自建 `views/interaction.rs` 文本提示处理允许/拒绝。这与 Grok
Build 的 blocking permission card 不同：Grok 审批会接管 composer 区域，使用
accent rail、工具说明/命令正文、radio option rows、数字/Tab 导航和 card/scrollback
焦点阶梯。用户要求沙箱执行审批与固定 Grok Build mirror 对齐。

本批目标是把 approval 改为 Grok-derived permission card；question 暂时保留既有
modal。Harness 继续是审批 identity、generation 和响应结果的唯一真源。

- 复用等级：B。保留 permission card 的 composer placement、height cap、accent rail、

  去除 Grok ACP、shell permission grant、bash grant persistence、syntect、MCP scope 和

- DSH-neutral seam：`DshInteraction::Approval` 保留 host `callId`；UI adapter 用它关联

- 稳定 identity/generation：沿用 request id + approval id + session generation；
  `callId` 只负责视图关联，不作为响应 identity。

  client-side cancelled outcome 不在 Harness contract 中，因此不显示或伪造这些动作。
- 将替换的旧模块：`views/interaction.rs` 的 approval 绘制分支和 runtime 的 approval
  modal/y-n 快捷分支；question response builder/modal 保留。

## 风险、回滚和依赖

- 风险：短终端下 permission height 可能挤压 transcript；callId 缺失或旧历史无法关联
  command；pending receipt 与 authoritative resolved 之间仍需保持卡片不可重复回答。
- 缓解：共享 height/render 几何，保留 tool/reason fallback，增加 80x24/窄屏 buffer、
  callId、输入和焦点测试。
- 回滚：恢复通用 Interaction modal 和旧 approval key 分支；DTO 的可选 callId 可独立
  保留且向后兼容。
- 依赖：只使用现有 ratatui/crossterm/textarea/shortcuts bar，不引入 Grok runtime
  crate 或新依赖。

## 实际修改

- 在 pager projection/session/control-plane 链路保留 approval `callId`，并更新 parity
  fixture 和单元测试，避免 UI 只能凭 tool name 猜测要审批的工具调用。
- 新增 B 级 Grok `permission_view` adaptation：审批卡替换 composer，保留 accent rail、
  50% 高度 cap、标题/命令折行、radio rows、hover/focus/pending 样式、选项 hit rect 和
  Ctrl+F 展开提示；来源及双端 SHA-256 已加入 `SOURCE_MANIFEST.md`。
- 将 approval 从通用居中 modal 拆出为 `Overlay::Permission`。该 overlay 不 dim
  transcript；Esc 只把焦点 park 到 scrollback，Enter/i/Tab 可重新聚焦，host resolved
  后才关闭卡片并恢复 composer。question 继续使用原 modal。
- adapter 用 `callId` 关联已流式呈现的 `DshRenderBlock::ToolCall`，复用 execute-tool
  projection 显示命令和描述；缺失关联时回退到 reason/tool name。
- 输入改为数字键立即提交、Enter 提交当前项、Tab/Shift+Tab/方向键/j/k 移动、鼠标
  单击选中和双击提交。response receipt 为 accepted/queued/pending 时保持本地 pending
  锁，直到 authoritative interaction 消失，防止重复响应。
- approval wire outcome 统一映射为 Harness 支持的 `allowed-once`/`rejected`，移除旧的
  无效 `denied`。未伪造 Grok `always approve`、grant persistence 或 client cancelled。
- 更新长期适配计划 M7 证据与 renderer closure inventory；增加 permission renderer、
  callId projection、focus park/refocus、host outcome 和 80x24 composer replacement 的
  semantic/buffer 测试。
