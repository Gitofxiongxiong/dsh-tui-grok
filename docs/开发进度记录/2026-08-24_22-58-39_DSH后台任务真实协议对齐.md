## 目标与背景

`deepseek-harness` 已经通过 `events.mux` 推送 `session/jobs`，其中任务状态为
`running | stopping | completed | killed | failed`，字段只有任务元数据；本批次将
`dsh-pager-grok` 的任务 pane 对齐该真实协议，并用 DSH Web 的排序与 live 语义替换
mock 专有的 activity/output 假设。Subagent 仍保持 unsupported，不向 Harness 添加
不存在的 subagent 能力。

## 设计契约

- 真源：`ctx.jobs` → ApiProxy `session/jobs` whole-set frame → `ControlPlaneStore`。
- 任务详情只读取 `id/kind/label/status/detail/startedAt/finishedAt`；不调用或模拟
  `job_output`，避免消费模型侧 output cursor。
- inline 顶部只显示 `running` 和 `stopping`；modal 保留已结束任务用于诊断。
- live 任务按 startedAt 升序；已结束任务按 finishedAt 倒序，和 DSH Web
  `packages/client/ui-jobs/src/client/JobListAction.tsx` 对齐。
- 本批次不添加 job-kill RPC；Harness 当前只有模型侧 `job_kill`，TUI 继续不显示伪造
  的 kill 操作。Subagent interrupt 保持原有 effect seam。
- 不修改 `/home/leo/code/deepseek-harness`；该仓库只作为只读协议与测试 oracle。

## 实际实现

- `TaskRow::is_live()` 对齐 DSH registry：`running` 与取消握手中的 `stopping` 才算
  inline live；`is_running()` 保留旧状态兼容，详情的 settled elapsed 使用
  `finishedAt`，不再按当前帧持续增长。
- inline Tasks 和 modal 均使用同一个排序器：live 按 `startedAt` 升序，settled 按
  `finishedAt` 降序并以稳定 id 打破平局。状态图标将 `stopping` 显示为 `!`，完成和
  失败分别显示 `✓/✗`。
- `TaskRow` 删除 DSH wire 不提供的 `activity/output/outputLines/outputTruncated/
  isMonitor` 投影；详情仅展示 `id/kind/status/detail`。mock fixture 改为四条真实
  `JobView` 生命周期样本：running、stopping、killed、completed。
- 未修改 `deepseek-harness`；任务停止仍没有 TUI job-kill RPC，continuable subagent
  的既有 interrupt effect 保持不变。真实 profile 不支持 subagent 时，catalog 不会被
  UI 伪造，Subagents 分组自然隐藏。
