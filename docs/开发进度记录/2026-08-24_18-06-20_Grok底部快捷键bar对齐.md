## 目标与背景

dsh-tui-grok 主画面底部 shortcuts bar 目前写死 `Enter:send / p:sessions / q:queue / Esc:clear/quit`，
窄终端再用 `compact(2, None)` 截成两个。这和 Grok Build 的产品逻辑不同：Grok 用
`ActionRegistry` + `build_hints` 按 composer / pane / turn 动态组 hint，再
`ShortcutsBar::compact(5, ShortcutsHelp)` 绘制。空 composer 自然变成 2 个
（`Shift+Tab:mode` + `Ctrl+.:shortcuts`），有可发送内容且 Shift+Enter 不可用时
变成 4 个（再加 `Enter:send` 和 `Alt+Enter:newline`）。

用户要求不要在 dsh 里另写一套 2/4 规则，而是把 grok-build 的代码拿来用。
功能点可以暂时不完善（cheatsheet overlay、interject、vim scrollback 等），
但产品逻辑和架构必须对齐 Grok。

- 风险：ActionRegistry 默认绑定依赖终端探测；stub 过粗会让 help 主键在
  Ctrl+. / Ctrl+X 之间选错。缓解：保守复用 grok 的 vscode-family / unknown
  规则，并保留 grok registry 单测。
- 回滚：恢复 `AgentView::render_shortcuts` 静态四 chip 和本批 vendor/shim。
- 依赖：已 vendor 的 `shortcuts_bar.rs` 与 `input/key.rs`，不引入 Grok runtime crate。
