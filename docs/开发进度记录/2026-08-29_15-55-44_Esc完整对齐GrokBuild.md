## 目标与背景

此前首页 Esc 只移植了 Grok 策略的一部分：运行时发送取消、空闲有草稿时
立即清空、空闲无草稿时吞键。当前 Grok Build 实际还包含双击确认状态机、
空 prompt 的 rewind 入口、cancel pending 重发，以及 overlay/selection 等抢键
优先级。因此已有实现虽然单元测试通过，真实交互仍没有与 Grok Build 对齐。

本次在独立 worktree `/home/leo/aidreamschool/dsh-tui-grok-esc-parity`、分支
`fix/grok-esc-parity` 中修复以下三个行为簇：

1. idle + 非空 prompt：第一次 Esc 显示 clear 提示，800ms 内第二次 Esc 清空；
2. idle + 空 prompt + 有历史：第一次 Esc 静默 arm，第二次打开 rewind picker；
3. running / cancel pending：Esc 保留草稿并发送/重发取消，取消后 1s 内抑制
   rewind arm。

## 风险、回滚和依赖

- 风险：DSH 没有 Grok 的原地 rewind API；用 fork/create-session 模拟时会产生
  新 session id/lineage，但可保持用户可见的历史截断和 prompt 恢复语义。
- 风险：重复取消存在乱序回执；必须按 operation identity 只清理最新 pending。
- 风险：新 picker 会影响 prompt pane 高度、焦点所有权和鼠标命中区。
- 依赖：本地 DeepSeek Harness mock、`/home/leo/.grok/bin/grok`、ttyd、
  xterm.js/Playwright。
- 回滚：还原本记录“计划修改范围”内的文件；worktree/分支可独立删除，不影响
  原工作区中用户已有的未提交修改。

## 实际修改

- 新增 `esc.rs`，把 Grok 的 app-level pending matcher 与 AgentView bare-Esc
  policy 抽成独立 reducer：800ms 双击窗口、1s cancel→rewind 保护窗、修饰键/
  release 过滤、超时和抢键退役规则均有确定性单测；`GROK_ESC_DOUBLE_PRESS_MS`
  仅作为 PTY 测试覆盖窗口。
- `AppShell` 现在按 Grok 顺序处理 pending action、overlay、selection、Ctrl+C 和
  未认领 Esc。非空 prompt 第一次显示 `Esc:press again to clear`，第二次才清空；
  空 prompt 且有用户历史时第一次静默、第二次打开 rewind picker；空历史吞键。
- 结构移植 Grok `overlay_list` 与 conversation rewind picker/confirm/executing/error
  视图、键盘和鼠标命中几何。DSH 没有原地 rewind API，因此选中第 N 个 prompt
  时以第 N-1 个用户事件为 `session.fork(atSeq)` 锚点，等待 host 返回 child id 后
  attach 并恢复所选 prompt；首个 prompt 使用 `session.create` 建立空权威 session。
  UI 不直接删改本地 transcript。
- `session.fork` async completion 现在解码并携带 child session id；runtime 增加
  fork completion/attach barrier，失败保留可关闭的错误面板。创建首轮空 session
  时保留当前 agent preset。
- 取消流程允许 `cancel_pending` 状态再次按 Esc 生成新 operation；回执只按最新
  operation identity 收敛，旧请求的失败/超时不能清除新重试。mock 第一次 cancel
  故意维持 running，第二次才发布 idle，以固定这条竞态路径。
- 新增 `pty-esc-parity.py`，覆盖双击 clear、静默 rewind、确认/执行/prompt 恢复、
  cancel retry 和终端恢复；`pty-smoke.py` 改用 Grok 的空闲 Ctrl+C 退出梯级，不再
  假设 Esc 会退出。
- 新增 ttyd+xterm.js+Playwright 对照脚本，在相同 1200×800/DPR 1 画布验证 DSH
  与本地 Grok 的 clear 提示文案，并留存 DSH picker/confirm 像素证据；不向真实
  Grok 模型提交 prompt。
- 更新 source manifest、测试说明和 M3.5 迁移状态。实际变更文件如下：
  - `crates/dsh-pager-bin/tests/mock-server.mjs`
  - `crates/dsh-pager-grok-ui/SOURCE_MANIFEST.md`
