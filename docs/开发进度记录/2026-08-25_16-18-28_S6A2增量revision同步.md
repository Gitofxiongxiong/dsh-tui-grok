# S6A2 增量 revision 同步

> 开始时间：2026-08-25 16:18:28 +0800
> 执行者：Codex
> 状态：已完成（S6A2；sticky/host pane/S7/browser gate 继续开放）

## 背景

- S6 已让 unchanged animation frame 避免全历史物化，但任一 content revision 仍会在
  `ScrollbackPane::sync_with_appearance` 中重新扫描全部 entry metadata。
- 现有 50k 测试只覆盖一次 cold sync 加若干不变帧，尚未覆盖长历史上连续
  `message/partial` 更新；这会掩盖流式尾部每次 revision 仍为 O(history entries) 的问题。
- 本批只闭合 revision delta 与增量同步，不提前混入 host pane 拆分、sticky composition
  或 S7 renderer 合并。

## 本轮目标

1. 由 host `Scrollback` 发布有界、可追溯的 content change delta；调用者错过日志窗口时
   必须显式回退 full resync，不能静默使用不完整范围。
2. 对不改变 topology/group/pending 语义的 in-place entry 更新，UI 只失效受影响 entry 的
   projection/materialization/height；新增、删除及全局语义变化继续走安全的 full sync。
3. 增加 50,000 entries + 连续尾部 revision 的 instrumentation，证明扫描量随 change range
   而不是历史长度增长，同时保持 viewport paint 有界。

## 合同

- delta revision 单调并覆盖 `(known_revision, current_revision]`；缺口、未来 revision、日志
  淘汰均返回不可增量同步信号。
- entry content 原位更新可报告窄范围；插入、删除、重排以及无法局部证明的语义变化必须
  标记 topology/global，UI 随即 full resync。
- incremental sync 不得保留已变化 entry 的 owned rich cache，也不能改变未变化 entry 的
  expansion/fold/selection 稳定 ID 状态。
- 性能断言同时统计 metadata scan 与 rich materialization，避免用“少 clone”替代“少扫描”。

## 风险与回滚

- 漏报变更会产生陈旧画面；所有 canonical mutation 入口与日志溢出都需单测。
- tool/group/pending projection 可能依赖相邻 entry；这类变更先保守 full sync，之后再单独缩小。
- 保留既有 full-sync 路径作为回滚边界；不执行 destructive git。
