# 命令事件保持空白会话

> 记录时间：2026-08-29 11:49:12 +0800
> 操作者/agent：Codex
> 状态：completed

## 目标与背景

官方斜杠命令已改走 `commands/execute`。真实 ttyd/xterm.js 验证发现：新会话执行
`/permission` 或 `/plan` 后，Host 的 `session.list` 仍正确发布 `blank=true`，但在
control-plane blank 尚未到达/短暂缺席的窗口里，TUI adapter 以
`transcript_len == 0` 作为 fallback。command lifecycle 会呈现为 Status transcript，
从而被误认为已经开始首轮对话，并永久锁住对话前 agent preset。

本批把 fallback 对齐 DSH 官方 `sessionBlank` 契约：只有 durable `turn/start` 才结束
blank。命令、plan/mode、goal、title 等 standalone plugin events 不结束 blank。

## 设计契约和复用依据

- DSH 真源：`deepseek-harness/packages/host/apiproxy/src/api-proxy.ts::sessionBlank` 明确
  以 `turn/start` 判断“conversation has started”，并说明 `/plan`、`/goal` 在 fresh
  session 上保持 blank。
- 长期计划：2.3 Host authoritative state、2.5 replay/live convergence、M10 真实后端验收。
- Grok 对应源码和测试：不涉及新的 Grok UI；继续使用既有 preset flag/picker。
- 复用等级：C，仅修正 DSH `SessionState -> GrokHostSnapshot` adapter fallback。
- DSH-neutral seam：`GrokHostSnapshot.session_blank` 不变；无新增 DTO/Intent/Effect。
- 稳定 ID 和 generation：继续使用当前 session/generation snapshot；不引入本地业务真源。
- 将替换的旧模块：仅替换 `transcript_len == 0` fallback，不修改 authoritative
  control-plane 优先级。

预期行为：

- `blank` 缺席时，history 无 `turn/start` 即保持 blank，即使命令 Status 已进入 transcript；
- history 出现 `turn/start` 后 fallback 为 non-blank；
- 真实 `/permission`、未知 slash、`/plan` 序列后 preset 仍可编辑，真正 prompt 后锁定。

## 风险、回滚和预期验证

- 风险：只看当前 history window 时，分页可能不含旧 `turn/start`。正常 control-plane
  baseline 提供 authoritative blank；fallback 对 `has_more=true` fail-closed 为
  non-blank，测试覆盖该保守条件。
- 回滚：回滚本记录对应单一 commit；不涉及 wire 或持久化迁移。
- 验证：host adapter 单测、workspace check/test、manifest/fixture/parity、真实
  ttyd+xterm.js+Playwright 命令前后 preset flag 与首次真实 prompt 锁定。

## 实际修改

- 文件：
  - `crates/dsh-pager-grok-ui/src/host_adapter.rs`
  - 本记录。
- 摘要：
  - 新增 `fallback_session_blank`，在 control-plane summary 的 `blank` 缺席时按
    DSH 官方 `sessionBlank` 契约检查 durable history：完整 history 没有
    `turn/start` 才是 blank；

    non-blank；authoritative control-plane 值仍拥有最高优先级；

    时仍保持 blank；加入 `turn/start` 或存在分页缺口后变为 non-blank。
