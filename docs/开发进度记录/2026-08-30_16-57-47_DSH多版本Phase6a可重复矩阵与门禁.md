## 目标与边界

- 按 D-R9 固化 `0.1.0-rc.8` 的独立 fixture、lockfile 与可重复 E2E/PTY 命令。
- 为 alpha.1、rc.2、rc.8 建立隔离 `DSH_HOME`、profile、依赖目录和精确包管理器的
  等价本地矩阵入口，并实际跑通三条命令。
- 增加 publish candidate 的 registry dependency gate，实际演练 rc.2 组合通过、
  含 alpha 组合失败两个方向；`doctor --release` 调用同一门禁实现。
- 将 fixture、conformance、support check 与三版本矩阵接入 GitHub Actions，配置
  path filter 与 scheduled 全矩阵；workflow 只落地文件，不 dispatch。
- 不改 registry status；rc.2 本批结束仍为 candidate。禁止 npm publish、
  dist-tag、git push、GitHub Release 与 workflow dispatch。

## 计划修改范围

- `compat/fixtures/dsh-0.1.0-rc.8/**`、`compat/README.md`。
- `scripts/` 下 registry gate 与本地版本矩阵入口、相关测试/CLI release doctor 接口。
- `.github/workflows/ci.yml` 及 `docs/GIT_PR_RELEASE_WORKFLOW.md` 必需对齐。
- 本进度记录与必要的 root package script/文档索引。

## 风险、隔离与回滚

- 所有真实验证只使用 `/tmp` 新建沙箱；绝不读取或改写真实 `~/.dsh` profile、
  sessions 或 credentials。沙箱路径在执行前登记，证据写入后清理。
- rc.8 必须使用自己的 fixture/lock/node_modules，不能复用 rc.2 lock 或一次性产物。
- registry gate 只允许 `npm view <name>@<exact> version` 读操作；不得执行任何写 registry
  命令。alpha 失败是预期门禁证据，不以忽略退出码伪装通过。
- workflow 无法在本机执行，因此验收依据是每个 job 的等价本地脚本实际运行结果，
  加 YAML/脚本定向测试；不 dispatch。
- 任何版本真实 E2E 回归失败即保留 candidate，不进入 6b；本批可整体 revert。

## 预期验证

- rc.8 独立 install/build/E2E/PTY 重复通过。
- alpha.1、rc.2、rc.8 三条本地矩阵命令全部通过，且打印各自 exact version/family/

- `git diff --check`。

## 实际修改与验证结果

### 独立 fixture 与 registry 单一真源

- 新增 `compat/fixtures/dsh-0.1.0-rc.8/`。package manifest 的 15 个 DSH direct
  dependencies 全部 exact `0.1.0-rc.8`，有独立
  `pnpm-lock.yaml`（SHA-256
  `68befeee891b0c6672b167a4917a0105fa8f986d6e31e9e348cdbdf3fce5cc37`）、
  workspace/profile policy、patch、entry、build check 与 E2E runner；全目录无 rc.2
  version/name 命中，未复制 rc.2 lock/node_modules。
- `scripts/dsh-matrix-config.mjs` 从 support registry 生成 GitHub matrix 或单版本 TSV；
  tag、commit、family、package manager、checkout env、source/fixture 都由 registry 派生。
  `.github/workflows/ci.yml` 与 `scripts/run-dsh-compat-matrix.sh` 中没有三条 DSH
  version/tag literal。`check-dsh-support.mjs` 将 matrix generator/runner 加入无第二
  真源检查，消费者从 3 个增为 5 个。
- 本地 runner 对每条 registry version 强制 exact checkout 检查，创建
  `/tmp/dsh-pager-matrix-<family-label>.*`、version-specific profile；npm family 使用
  独立 fixture node_modules，source-only family 用自身 checkout 的精确 package
  manager build。退出时只在严格路径前缀匹配后删除临时 home。

### Registry dependency gate 与 doctor

- 新增 CLI 内置 `registry-gate.js`，收集 publish candidate 的 `dependencies` 和
  非 optional peers；range/local spec/冲突 exact version 在网络查询前失败，对每个
  唯一 exact row 执行只读 `npm view <name>@<version> version --json`。仓库脚本与
  `doctor --release` 共用该实现；普通 doctor 不进行 registry 网络访问。
- rc.2 正向：默认 runtime-apiproxy-v1 + CLI manifest 共 17 个唯一 exact
  non-optional dependencies 全部返回同版本，exit 0。
- alpha 反向：`node scripts/check-registry-dependencies.mjs
  packages/dsh-pager-runtime/package.json` 返回 exit 1；Cordis/Schemastery 可用，18 个
  `@deepseek-ai/dsh-*@0.1.2-alpha.1` row 全部明确报告 E404。该预期失败由外层
  `test "$status" -ne 0` 断言，没有 `--force` 或忽略门禁。
- CLI unit 新增收集规则、range/local/missing 与 doctor release 复用测试；CLI
  结果 2 files / 21 tests 全绿。

### CI 文件

- `ci.yml` 保留 Rust 三平台 job，`verify-ts + contracts` 运行 build/typecheck/unit、
  两个 12/12 conformance、protocol fixture、support、pack、registry availability，
  并产出 version-independent TS/native artifact。
- `dsh-matrix` 由 registry 动态生成三个独立 job。rc.8/rc.2 只恢复 core/native
  artifact并安装各自 fixture；alpha checkout 目录为 source workspace 明确要求的
  `../deepseek-harness-latest`，使用 registry package manager 构建。三个 job 都先
  clone exact tag 并断言 HEAD commit、使用独立 home/profile/node_modules。
- adapter/support/compat 路径由 `dorny/paths-filter` 触发全矩阵；scheduled step
  不执行 diff filter，job output 强制为 true，每周一 03:17 UTC 运行全矩阵。
  workflow YAML 已本地 parse 并断言四个 job/dynamic matrix；按约束未 dispatch，
  因此不把远端 workflow 执行状态写成验收事实。
- `docs/GIT_PR_RELEASE_WORKFLOW.md` 已同步 required checks、path filter/schedule 与
  read-only npm view 副作用；没有改变 release/publish workflow。
