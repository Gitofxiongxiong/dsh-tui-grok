# S6B host pane 边界拆分

> 开始时间：2026-08-25 16:24:14 +0800
> 执行者：Codex
> 状态：已完成（host pane 边界；sticky/S7/browser gate 继续开放）

## 背景

- S6A2 已由提交 `91d77d3` 关闭连续 partial revision 的全表扫描，但 production
  `ScrollbackPane`、`ProjectionInfo`、viewport materialization 与 Buffer painter 仍住在
  `views/transcript.rs`；该文件因此同时承担 host glue、legacy oracle 与视觉算法。
- 目标拓扑已指定 `scrollback_adapter/host_pane.rs` 是唯一理解 DSH Scrollback/Fenwick
  的 production 边界。本批先做纯职责迁移，保持像素与交互合同不变，再在后续独立批次
  接 sticky composition 和删除 `RichTranscript`。

## 本轮目标

1. 新建 `scrollback_adapter/host_pane.rs`，迁入 production pane 状态、revision sync、
   projection metadata、viewport/materialization、visible-line 与 direct-Buffer paint。
2. Runtime 直接依赖 adapter host pane；`views/transcript.rs` 只保留 renderer-neutral
   semantic materializer、legacy `RichTranscript` oracle 及其测试，并显式复用迁出的 DTO。
3. 保持 stable ID、fold/group/pending、selection/hit-map、timestamp、Fenwick anchor、50k
   instrumentation 行为完全一致；本批不顺手改像素。

## 合同

- host pane 是 adapter，不拥有历史真源；所有 canonical entry、revision 与高度索引仍由
  `dsh_pager::Scrollback` 拥有。
- 迁移前后 runtime 只保留一条 production painter；不得复制一份 pane 后让双路径并存。
- `views/transcript.rs` 可以在过渡期提供 `pub(crate)` semantic materializer 给 host pane，
  但不得重新拥有 revision/window/runtime state。
- 现有 50k cold/hot/partial 统计、fold/group/pending 与 Buffer paint tests 必须原样通过。

## 风险与回滚

- Rust 模块可见性与测试私有字段访问会产生机械性编译错误；只开放 crate-private seam，
  不扩大公共 API。
- 循环模块引用必须保持单向数据依赖：transcript materializer 接受 host DTO，不得调用
  pane state 或 Scrollback。
- 以提交 `91d77d3` 为干净回滚点；不执行 destructive git。
