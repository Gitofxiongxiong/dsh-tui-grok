# 主分支排空 PTY 退出尾帧

> 记录时间：2026-08-30 10:20:16 +0800
> 操作者/agent：Codex
> 状态：completed

## 目标与背景

- Rust 1.98 workspace all-features Clippy 门禁闭合后，`scripts/e2e.sh` 的
  protocol/source/parity/check/test/clippy/build 均通过，最后 full PTY 报
  `terminal surface was not restored`。
- 该竞态在 alpha 分支 `PTY退出帧排空` 记录中已定位：`pump()` 每次
  只读一个 16 KiB chunk，`waitpid(WNOHANG)` 一旦报告子进程退出，脚本
  立即断言 restore，可能尚未消费 master PTY 已缓冲的尾帧。
- 目标是在确认子进程正常退出后排空当前可读数据，不放宽 terminal
  restore 断言，然后重新完整运行 E2E 并 push。

## 设计契约

- 复用等级：D（测试驱动基础设施）；产品 TUI 退出逻辑不改。
- 只在 `waitpid` 已确认目标子进程退出后排空，使用零超时 `select`，
  不增加 sleep、不阻塞、不掩盖未退出进程。
- EOF、EIO、EBADF 表示 PTY 已关闭，正常停止排空。
- 恢复断言保持原样，仍必须同时观察到 `ESC[?1049l` 和 `ESC[?25h`。

- 风险：排空循环若使用非零超时可能卡住；固定 `select(..., 0)`。
- 回滚：revert 本记录对应单独提交；无数据迁移。
- 验证：`python3 -m py_compile scripts/pty-smoke.py`、full PTY 连续重复，
  `scripts/e2e.sh`、`git diff --check`。

## 实际修改与验证

- 在 `pty-smoke.py` 新增 `drain_ready()`：子进程退出后用零超时 `select`
  持续消费 master PTY 已经可读的 16 KiB chunks，并将每个 chunk 同步喂给
  原有 output/screen parser；EOF、EIO、EBADF 均按 PTY 关闭语义退出。
- 只在 `waitpid` 确认目标子进程正常退出且 exit code 为 0 后调用该 helper；
  原 restore 断言未放宽，仍要求同时观察 `ESC[?1049l` 和 `ESC[?25h`。
- `python3 -m py_compile scripts/pty-smoke.py`：通过。
