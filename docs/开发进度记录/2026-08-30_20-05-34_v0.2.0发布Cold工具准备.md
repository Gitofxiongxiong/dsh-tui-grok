# v0.2.0 发布 Cold 工具准备

## 目标

- 修复正式发布 workflow 的 registry cold job：在 Ubuntu runner 显式安装 `ripgrep`，
  再执行依赖 `rg` 的 cold/warm/offline、doctor/smoke 与 PTY 演练。
- 保持 `v0.2.0`、已发布 npm versions、dist-tags 与来源 artifacts 不变。

## 背景与证据

- 恢复 workflow commit `14960c1a5f775ea589440b9ab835f75f9bf80d6a` 的 PR 与 main
  CI 已全绿。
- recovery run `33310487508` 已通过 metadata、来源 JS/native artifacts 恢复、五个平台
  native registry integrity/staging 校验与 runtime integrity 校验。
- registry cold job `99254664313` 在 `install pnpm and ripgrep` step 失败；日志显示该 step
  实际只运行 `corepack enable` 与 `command -v rg`，Ubuntu runner 没有预装 `rg`，exit 1。
- CLI `@dsh-pager-grok/cli@0.2.0` 尚未发布；publish CLI 与最终 registry gate 因依赖关系
  均未运行。

## 设计契约

- 仅修改 runner 工具准备，不改 package source、tarball、协议、TUI 或 cold 演练内容。
- 使用 Ubuntu 官方 apt repository 安装发行版 `ripgrep`，随后用 `command -v rg` 留下存在性
  断言；`corepack enable` 保持原位。
- recovery 继续使用 `release_tag=v0.2.0`、`resume_run_id=33309459911` 与
  `confirm=publish-v0.2.0`，复用首次正式 run 的确切 artifacts。
- cold/PTY 未绿前仍不发布 CLI；最终 registry/provenance 未绿前不统一移动 dist-tags、
  不创建 GitHub Release。

## 风险

- apt repository 暂时不可用会使 cold job fail closed；不会绕过 `rg` 依赖或继续 CLI publish。
- 重跑会再次读取并校验已发布 native/runtime；安全重入逻辑必须保持不变。

## 回滚方式

- PR 合并前关闭 PR；registry 状态不变。
- recovery run 再失败时保持 CLI 未发布、其余包 dist-tags 不变，登记日志后停止。
- 不移动 Tag、不覆盖或 unpublish 任何 npm version。

- 在与 runner 同系的 Ubuntu 环境确认 apt package `ripgrep` 可解析，且安装命令为非交互、
  `--no-install-recommends`。
