## 设计决定

- 每个独立工作批次先创建一份时间戳记录，再修改目标文件；
- 一个 Git commit 只能有一个主进度记录，且 commit message 必须包含：
  Progress-Record: docs/开发进度记录/<record-file>.md
- 一个记录不得跨多个独立 commit；若需要拆分，先创建新的记录；
- commit 前检查暂存区只能包含该记录和它列出的目标文件；
- commit hash 不在提交前硬编码到记录中，以 commit trailer 和记录路径作为
  可验证绑定，避免为回写 hash 产生无意义的第二个 commit。
