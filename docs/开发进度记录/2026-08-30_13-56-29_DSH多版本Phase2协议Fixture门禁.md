## 目标与背景

执行 Phase 2 第二批：明确 Rust fixture 目录的 canonical 所有权，建立
TypeScript mirror 的完整 JSON 文件清单/深度相等门禁，并用双端测试把 method
catalog、协议版本、错误 kind 与现有代码事实绑定。

## 设计契约和复用依据

- 对应长期计划章节：§6.1、§16.1、§19 Phase 2。
- D-P2-1：不在 Rust 新建 `MuxFrame`/`HostFrame` 判别 union。Rust 强类型拥有
  line carrier、hello/attach/subscribe/respond 与业务 DTO；mux/host frame 语义
  由 fixture 目录和双端测试锚定。
- catalog 基线：55 unary、5 control、5 notification；`TUI_PROTOCOL_VERSION=1`；
  8 个既有 `TuiErrorKind`。
- Rust 当前实际使用 method 清单来自 `crates/dsh-pager/src` 的 request/notification
  字符串；Rust 测试至少验证这些字符串全部存在于 canonical catalog。
- 复用等级：A0（现有 hello fixtures、codec 测试与 serde DTO）。

## 风险、回滚和依赖

- 风险：README 只存在 canonical 目录，因此“文件清单完全一致”明确指 JSON fixture
  清单；检查器比较两侧全部 `*.json`，非 fixture 文档不参与镜像比较。
- 风险：顺序差异可能掩盖 catalog 漂移；JSON 深度相等保留数组顺序，使 catalog
  重排也成为显式变更。
- 风险：可读错误路径不足会降低门禁定位能力；深度比较需报告 JSON path 及两侧值。
- 回滚：本批独立 commit 可整体 revert，无数据或运行时迁移。
- 依赖：Python 3、Vitest、Rust/serde_json。

## 实际修改

- 在 Rust canonical fixture 目录新增所有权 README，明确 D-P2-1：Rust 强类型
  边界和当前 JSON frame carrier 的分工，不新增双端 frame union。
- canonical 与 TypeScript mirror 各新增 method catalog（55/5/5）、协议版本 1、
  8 个错误 kind；两侧保留既有 hello request/result，共 5 个 JSON fixture。
- 检查器改为比较完整 `*.json` 文件名集合和所有 parsed JSON 值；缺失、额外、
  解析失败与字段/数组/值漂移均输出具体文件和 JSON path。
- TypeScript 测试将三个 method 常量目录、65 总数、协议版本与错误码 key 绑定
  fixture；Rust 测试绑定协议版本、两个 hello 的 serde 往返，并验证当前
  `crates/dsh-pager` 使用的 36 个 method 均在 canonical catalog 中。
- 未改任何生产源码、wire、method 字符串、协议版本或错误 kind。
