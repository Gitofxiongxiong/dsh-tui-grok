# /resume 冷会话标题投影修复

## 目标

修复 native Grok `/resume` 历史选择器把所有历史会话渲染为 `(no prompt)` 的问题。目标是让已有冷会话在第一次列表读取时能够恢复 `title` 投影，并让 embedded profile 持久化后续投影。

## 背景与根因

Harness 的 `session.list` 对冷会话只读取 `sessionProjectionCache.cachedSnapshot()`；缓存缺失时不读取历史日志，因此外置 adapter 收不到 `projections.values.title`。`tui-embedded` profile 同时没有挂载 `session-projection-cache`，导致新旧冷会话都缺少该列。

## 设计契约

- 已有缓存行继续走同步零日志读取。
- 缓存缺失且部署挂载投影缓存时，列表使用 `coldSnapshot()` 重放并回写一次；之后恢复为缓存读取。
- 缓存服务仍是可选能力；未挂载它的组合保持没有冷投影列的既有契约。
- embedded profile 挂载 `session-projection-cache`，其配置与 web profile 一致；`title` 由现有 session-title 投影提供。
- 不修改 Grok vendor 的 `(no prompt)` 占位逻辑；没有标题的会话仍显示占位文本。

## 风险与回滚

冷列表首次遇到无缓存会读取完整日志，列表响应可能比纯缓存路径慢；读取失败必须降级为无投影列，不得阻断列表。若验证显示性能或组合兼容性不可接受，可回滚冷回填逻辑，仅保留 profile 缓存挂载。
