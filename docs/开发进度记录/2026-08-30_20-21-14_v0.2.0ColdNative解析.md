# v0.2.0 registry cold install native 解析修复

> 操作者/agent：Codex
> 状态：completed

## 目标与背景

`v0.2.0` 第三次 recovery workflow run `33311024658` 已通过 Tag/source
artifact 恢复、五个 native 与 runtime registry integrity 门禁，但 registry cold
install 在 `scripts/audit-cold-install.mjs` 中对
`node_modules/@dsh-pager-grok/native-linux-x64-gnu` 执行 `realpathSync` 时失败。

本地用来源 run `33309459911` 的精确 CLI artifact 可重现同一失败；
`pnpm list --depth Infinity` 和 lockfile 均证明 native `0.2.0` 已安装，二进制
也为 executable。根因是 pnpm isolated layout 不会把 CLI 的 optional native
dependency 提升为 cold prefix 的直接依赖；它位于 `.pnpm` virtual store 并可从
CLI manifest 创建的 Node `require` 上下文精确解析。

## 设计契约和复用依据

- 对应长期计划章节：`DSH_MULTI_VERSION_COMPATIBILITY_PLAN.md` §17.2、§19 Phase 6
  与 §21.6；`GIT_PR_RELEASE_WORKFLOW.md` §7–§8。

  graph、tarball、DSH wire、TUI 行为或可见视觉。
- native 必须相对已安装 CLI manifest 使用 `createRequire(...).resolve()`
  解析；解析后真实路径仍必须位于 cold prefix 的 `node_modules` 下，不得
  因放宽路径而接受 workspace/sibling checkout。
- Grok source path/commit/SOURCE_REV：不适用（无 Grok 源码或 UI 变更）。
- 复用等级：D（发布工具链，不进入 Grok UI 边界）。

## 风险、回滚和依赖

- 风险：Node package `exports` 可能禁止直接解析 `package.json`。native
  package 当前无 `exports` 限制，但实现应只依赖本次已打包的精确 manifest
  契约并由真实 registry rehearsal 复核。
- 风险：解析到工作区或全局 package 造成假绿；保留 realpath 边界检查并
  增加越界负例。
- 回滚：回滚本批单一 commit 即恢复旧的严格 hoist 假设；不改变 registry
  已发布内容。
- 依赖：继续复用 formal source run `33309459911` 的精确 artifacts，
  不使用新 rebuild 替代 Windows native。

## 实际修改

- `audit-cold-install.mjs` 先定位 root CLI manifest 的 realpath，再用
  `createRequire(cliManifestPath)` 解析 optional Linux native manifest。CLI 和 runtime
  保留 root dependency 定位，三个候选包统一执行真实路径边界和 manifest
  dependency 审计。
- cold `node_modules` 边界改为 `path.relative` + `path.sep` 语义，既接受
  `.pnpm` virtual store 内路径，也拒绝 sibling prefix 和绝对路径逸出。
- rehearsal 的 PTY binary 使用相同 CLI-relative resolution 定位，并在 PTY
  前显式检查 executable bit。
- 新增 Node test 构造不存在 root native symlink 的 pnpm isolated layout，
  同时构造 native 指向 cold prefix 外的负例；已通过 `verify:ts` 自动执行。
- 发布 checklist 追记 recovery run `33311024658` 的精确失败与本地
  registry rehearsal 通过证据。
