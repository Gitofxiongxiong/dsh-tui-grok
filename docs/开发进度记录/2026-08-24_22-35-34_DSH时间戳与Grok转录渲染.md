## 目标与背景

按照上一份时钟触发点分析，把 DSH `SessionEvent.time` 保留到转录 DTO，建立
DSH 专属的 User/Agent 时间触发契约，并在当前 Grok-derived transcript renderer
中接入时间显示。同步修复工具边界导致的 Agent surface 时间语义，保持 replay/live
使用同一权威事件时间。此次不引入 Grok agent、shell、ACP 或 runtime 依赖。

## 预期行为

- User 只在 `user/message` 被 host 接受后使用该事件的 `time`；
- Agent 每个文本 surface 只在第一个非空 `assistant/chunk` 文本 delta 设置时间；
- Thinking、ToolCall、ToolResult、Context、Status 不显示时间；
- 工具调用结束当前 Agent surface，后续文本 surface 使用新的稳定身份/时间；
- 无效或缺失时间只走显式本地 fallback；
- replay 不使用恢复时间覆盖事件时间；
- UI 时间列不进入复制文本和 selection 内容；
- `show_timestamps` 是 UI appearance 状态，不产生 DSH RPC。

## 风险、回滚和依赖

- DTO 增加可选字段，必须保持旧 fixture 反序列化兼容；
- Agent surface identity 变化可能影响 anchor、selection 和 partial fixture；
- 时间列会改变 wrap/height/hit-test，必须补几何测试；
- Grok 基准截图若无法启动，只能记录为 partial，不能声称视觉 parity；
- 回滚方式：恢复本记录列出的代码/文档文件，保留已有用户未提交修改。
