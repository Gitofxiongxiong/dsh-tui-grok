# Execute 工具折叠说明与详情展开

## 目标

- Execute 工具折叠态展示 Harness 提供的人类可读说明，而不是直接暴露原始命令。
- 使用与 Grok Build 一致的折叠/展开提示符，并保留运行状态、左侧轨道和工具语义样式。
- 确认并覆盖双击工具行后展开命令、工作目录、输出及退出状态的交互。

## 背景

当前前台 `bash` terminal card 已携带 `description`，但折叠提示符仍使用普通菱形，用户不容易判断该行可展开。后台 `bash` 使用 generic execute card，说明位于 call content，当前折叠标题会退化为原始命令。运行时已有双击命中与折叠切换链路，但缺少 Execute 详情的端到端状态回归证据。

## 设计契约

- Grok 对应源码和测试：`grok-build/crates/codegen/xai-grok-pager/src/scrollback/blocks/tool/execute.rs` 的 collapsed description、expanded command 与 foldable 规则。
- 复用等级：B（保留 Grok 的展示层级和折叠状态语义，适配 DSH-neutral `DshToolCallView`）。
- DSH-neutral seam：只消费 adapter 已投影的 terminal/generic call view，不解析 Harness RPC 或工具私有 JSON。
- 新增 DTO/Intent/Effect：无；继续使用现有 entry identity、display mode 和鼠标双击切换路径。
- 稳定 ID 和 generation：不变；展开状态继续按 render entry ID 保存。
- 将替换的旧模块：不新增平行模块，仅修正 transcript Execute 卡片的摘要提取和提示符。
- 失败测试、PTY/golden 和回滚：增加语义渲染及双击展开测试；必要时以本提交整体回滚。

## 风险

- generic execute 的 call content 既可能是说明，也可能包含额外正文，提取时不得吞掉非说明内容。
- 展开提示符与分组标题共享样式路径，修改时不得破坏 read/search 等工具组折叠。
- 双击依赖可见行命中，测试需要覆盖真实 runtime 鼠标事件而不只直接调用 pane toggle。

- terminal execute 继续读取 Harness 的 `description`；generic execute 现在从 call content 提取后台 bash 的说明，并去掉说明开头重复的 `Run/Running`。
