## 目标与背景

- 用户确认流式输出期间上下滚动仍未修复，允许完全参照或直接复用 Grok Build 源码。
- 现有 `TranscriptViewportState` 与增量高度测试均通过，只证明绝对 `scroll_top`、
  transient estimate 和 anchor 的局部不变量；现有 PTY smoke 没有持续 token 流，也没有
  在流式未结束时断言滚轮输入的可见移动、停驻和向下恢复。
- 当前 DSH runtime 每轮先 drain 最多 256 条通知并绘制，再读取一个 crossterm 事件；
  Grok 固定源码把 ACP batch 限制为 32，输入队列非空时禁用 ACP arm，并合并已缓冲输入。
  Grok 上游 `wheel_scrolls_viewport_during_streaming_turn` 明确把该公平性缺口登记为
  “can't scroll while it's streaming”的根因。
- 当前 DSH 还把每个原始 SGR wheel report 直接换成固定 3 行，缺少 Grok
  `MouseScrollState` 的 terminal profile、wheel/trackpad 归一化、16ms cadence、方向翻转、
  backlog cap/coast 和 scroll clock；事件 flood 会造成逐事件重绘或过量移动。

## 风险、回滚和依赖

- 风险：原生 mouse state 依赖 terminal brand/multiplexer 和 appearance settings；只移植所需
  中性类型及环境覆盖，默认值必须与固定 Grok snapshot 一致。
- 风险：合并输入时若遗漏 scroll clock，短 wheel/trackpad gesture 可能积累不足一行而不动；
  PTY 必须覆盖事件后 tick/finalize。
- 风险：输入优先不能反向饿死通知；输入 batch 有界，通知仍按 32 条批次推进。
- 风险：vendor 复制和本地 `scroll_log` seam 必须更新 hash、许可证说明和 source checker。
- 回滚：回退本记录对应单一 commit；不修改持久化会话和 Harness 数据。
- 依赖：本机 `/home/leo/aidreamschool/grok-build` 固定镜像、Rust toolchain、Node mock、PTY、
  ttyd、xterm.js 与 Playwright。

## 实际修改

- 先构造持续流式回归入口：mock Harness 在收到 `stream scroll smoke` 后先输出 240 个
  稳定 `SCROLL-MARKER` 行，再以 30ms cadence 追加最多 2000 个 `TAIL-LIVE` delta；
  `scripts/pty-stream-scroll.py` 在流尚未结束时真实发送 SGR wheel report，并断言
  up、gesture settle 后停驻、down、fully-clamped overscroll 恢复 follow 和终端恢复。
- 修复前执行该 PTY，旧 fixed-3 路径在“Zed + forced wheel + scroll_lines=1”下把一个原始
  report 从 marker 213 跳到 205；fixture 加入 Markdown hard break 后把每个 marker 固定为
  一个视觉行，消除“多个 marker 被 soft-break 合并”的测试噪声。
- 从固定 Grok mirror 原样 vendor：
  - `input/mouse.rs`（1451 行，SHA-256 与上游一致）；
  - 相邻 `input/mouse/tests.rs`（1879 行，SHA-256 与上游一致）；
  - `appearance/scroll_mode.rs`（67 行，SHA-256 与上游一致）。
- vendor `input/scroll_log.rs` 保留 Grok JSONL flight-recorder/state-machine observation
  契约，只把 `~/.grok` / `tracing` seam 改为 temp 目录
  `dsh-scroll-log-*.jsonl` 和 DSH file-backed diagnostic；manifest 同时记录上下游 hash。
- `appearance::cache` 接入 Grok 的 `GROK_SCROLL_SPEED`、`GROK_SCROLL_MODE`、
  `GROK_INVERT_SCROLL`、`GROK_SCROLL_LINES` thread-local cache/default/clamp 语义；
  `ScrollMode` 直接使用上游 value type。
- terminal seam 扩展为 Grok mouse profile 使用的完整 `TerminalName` /
  `MultiplexerKind` 枚举，并从常见 TERM/TERM_PROGRAM/环境标志识别 native terminal、
  xterm.js embed、tmux/screen/zellij/cmux/herdr；不引入上游探针和 capability runtime。
- production runtime 的主 transcript wheel 路由到 `MouseScrollState`：
  - 原始 report 先做 terminal/multiplexer profile、wheel/trackpad、speed/lines/invert 定价；
  - 16ms cadence 合帧，方向翻转取消旧 backlog，fractional carry、viewport-relative cap、
    tapered coast 和 80ms finalize 均保留上游实现；
  - signed line delta 再进入现有绝对 `TranscriptViewportState`，DSH scrollback/session
    继续是唯一内容真源；
  - overlay owner 保持原路由；overlay 打开时取消隐藏 transcript 的 active mouse stream。
- production event loop 按 Grok `event_loop.rs` 的公平性重排：
  - loop top 最多合并 256 个已缓冲 terminal event，并在通知之前处理；
  - input backlog 存在时本轮不 drain notification；
  - notification batch 从 256 收到 Grok 的 32，并在 drain 中每条前 fail-closed 检查新 input；
  - active mouse stream 的 deadline 与 33/50ms 普通 poll 取最小值，短手势不会等动画 tick；
  - scheduler accounting 仍覆盖每个实际处理的 DSH notification。
- 更新 `SOURCE_MANIFEST.md`（79 rows、revision/hash/许可证审计）、transcript 交互契约、
  Cargo dev dependency/lockfile，并新增固定 budget 回归断言。
