## 目标与背景

当前 TUI 把 `normal`、`plan`、`danger-full-access` 拼成了一个自有三档
`SessionMode`，并通过 `Shift+Tab` 循环。这与 DSH 的真实能力边界不符：Plan 是独立
会话能力，permission preset 是另一套独立能力；同时审批卡的 “don't ask again”
选项会暗中切换整个会话模式，难以理解且不能准确表达 DSH 行为。

本批次纠正为 DSH 官方形态：Plan 只由 `/plan` 管理；permission 只由
`/permission` 管理；TUI 仅复用 Grok 的 `Ctrl+O` 快捷键切换 YOLO。YOLO 打开时
提交官方命令 `/permission danger-full-access`，关闭时提交
`/permission workspace-write`。Plan 与 YOLO 投影、显示和生命周期互相独立。

## 风险、回滚和依赖

- 风险：projection 到达可能晚于 prompt receipt；用 operation request id 约束 pending，
  仅在相同请求完成或目标 projection 到达时回收，避免旧 completion 覆盖新状态。
- 风险：宿主未暴露 `permissions.options` 时无法证明官方 preset 可用；此时禁用切换并
  显示可诊断状态，不猜测或写 raw event。
- 风险：移除私有 RPC 会改变内部协议方法集合；同步修改 Rust/TypeScript codec、server、
  mock 和 fixture 检查，确保不存在半迁移调用方。
- 依赖：DSH base bundle 注册 `workspace-write`、`danger-full-access`；ApiProxy 保持
  `session.prompt` 斜杠命令路径。
- 回滚：回滚与本记录绑定的单一 commit，可整体恢复三档实现；不需要迁移持久数据。

## 实际修改

- 文件：与“计划修改范围”完全一致。新增 `src/session_controls.rs`；删除
  `src/session_mode.rs`、server `src/session-mode.ts` 及其专用测试；未修改计划外文件。
- UI/交互：
  - 将 shell action 改为 Grok `ToggleYolo`，普通 prompt 和审批 overlay 均接受
    `Ctrl+O`；`Shift+Tab` 回归普通 prompt 输入，不再拥有模式语义；
  - 用 Grok action registry 中的 `Ctrl+o:yolo` 替换上游通用 prompt 中不适用于 DSH
    的 `Shift+Tab:mode` hint；
  - Plan 与 permission 分别从 `plan`、`permissions` projection 派生，prompt 同时支持
    独立的 `plan` / `YOLO` chip，状态栏分别报告两者；
  - 审批卡只保留 “Yes, proceed” / “No, reject”，审批期间仍可 `Ctrl+O`，不再由
    “don't ask again” 暗改会话权限。
- effect/协议：
  - `ToggleYolo` 根据权威 permission preset 在 `danger-full-access` 与
    `workspace-write` 之间切换，并验证目标存在于 host `permissions.options`；
  - 唯一写路径为 `session.prompt`，mode 为 `steer`，文本为官方
    `/permission <preset>`；pending 按 request id 隔离，目标 projection 到达后回收；
  - 删除 Rust/TypeScript 的 `SessionModeId`、`tui.setSessionMode` codec、server gateway
    分支以及直接拼装 plan/sandbox/approval 事件的实现。
- mock/来源：集成 mock 改为互相独立的 Plan 与 permission projection，并实现
  `/plan`、`/permission` 官方命令响应；SOURCE_MANIFEST 更新为本次实际的 Grok 复用和
  DSH 适配边界。
