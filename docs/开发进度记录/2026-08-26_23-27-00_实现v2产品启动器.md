## 目标与背景

实现 `docs/PRODUCT_PLUGIN_LAUNCHER.md` 当前推荐 v2：单一 `@dsh-pager-grok/runtime`
Bundle、hermetic `@dsh-pager-grok/cli`（私有精确版本 DSH/pnpm、官方 `dsh plugin`
冷启动、热启动跳过、平台 optional native 就地 spawn、doctor/update/uninstall/repair）。

## 设计契约和复用依据

- 对应计划：PRODUCT_PLUGIN_LAUNCHER.md v2 PR 1–2、4 的控制面；TTY T1–T8；
  不解析全局 `dsh`；backend 为 `process.execPath` + `require.resolve('@deepseek-ai/dsh/lib/bin.js')`。
- Grok：无 DSH profile 启动器。forwardExit 对齐社区 `dsh-TUI/bin/dsh-tui.js`（C）。
- 不复制 Grok runtime shell。

## 风险、回滚和依赖

- 风险：`@deepseek-ai/dsh@0.1.0-rc.8` 安装体积大 → 可接受（v2 确定性优先）。
- 风险：本机无干净隔离 `DSH_HOME` 的完整 cold start → 用单元测试覆盖 bootstrap argv，
  真实 plugin add 在有 harness 时尽量跑。
- 回滚：删除 runtime/cli 包与脚本。
- 依赖：已发布 native-linux-x64-gnu；workspace DSH 针 `0.1.0-rc.8`。

## 实际文件与摘要

- `@dsh-pager-grok/runtime`：单一 Bundle，assemble 把 protocol/server/recovery 打进 `lib/`，
  patch 引用 `runtime/server` 与 `runtime/recovery`，依赖全为精确 `@deepseek-ai/*`，无 `workspace:*`。
- `scripts/assemble-runtime.mjs`、`scripts/verify-runtime-pack.mjs`。
- `@dsh-pager-grok/cli`：私有 `@deepseek-ai/dsh@0.1.0-rc.8` + `pnpm@11.20.0`，optional native 包，
  冷启动 `dsh plugin add runtime@ownVersion`，热启动 skip，产品 argv 注入 node+bin.js+profile，
  doctor/update/uninstall/repair，不解析全局 dsh。
- `tui-server` hello `serverInfo.version` 改为所属 `@dsh-pager-grok/*` package.json 的 version。
- 已 `npm publish` `@dsh-pager-grok/runtime@0.1.0` 与 `@dsh-pager-grok/cli@0.1.0`（public）。
